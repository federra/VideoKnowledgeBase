## 一、角色、动作与对象权限

### 1、动作目录及初始权限包

角色代码：R=reader（使用者只读），E=editor（资料／知识编辑），V=reviewer（审核者），A=analyst（评测研判者），O=operator（运行配置者），M=administrator（成员权限管理员）。角色本身不赋权，只有绑定有效Grant、动作和对象范围后才生效；可组合，同一个人兼有编辑和人工审核权不被禁止，PRD的双审指AI与人工，不擅加“两名不同人工”条件。

下列每个代码是独立动作，逗号仅为压缩相同分配，不是组合权限字符串。初始化只登记角色与动作，不默认给全体成员组织级授权。

| --- | --- | --- |

管理员无隐含内容、知识批准、标准生效或密钥读取权；如需这些能力必须显式组合角色和对象授权。grant.manage可在其治理范围显式授予初始权限包，自我授权也是独立受审计操作，不能通过“我是管理员”绕开双审。成员／角色定义为组织级配置，member.manage、role.manage、model.configure、audit.read只接受org范围Grant；限定业务或单对象的这些动作不得修改整个组织。grant.manage的可授予范围不得超出治理Grant：org治理可授org／business／明确对象，business治理仅授同business范围，单对象治理仅授同对象同scope_kind；不得将共享知识对象授权作为单业务治理的扩大通道。scope匹配在写入前后校验并审计。首个组织管理员由S05本地受控开户流程建立，不通过开放接口自注册提权；本册不新增登录页面。

### 2、范围匹配与派生依赖

一次动作许可要求：当前会话成员属于同组织且未停用，Grant未撤销、未到期，role_actions含精确动作码，scope覆盖本次目标。默认拒绝，不支持隐式通配符；动作在同一目标上可由多份有效Grant取并集，但不同依赖对象分别检查后取交集。角色变更影响现有引用该角色的Grant，必须推进组织authz_version并写审计。

| Grant范围／目标 | 覆盖规则与关联路径 | 不能由此得到的权限 |
| --- | --- | --- |
| org | 当前组织中该动作允许的对象；仍执行业务筛选与版本规则 | 跨组织、跳过审核、解锁冻结记录 |
| business | source／work按business_code；知识按请求版本knowledge_businesses包含当前业务 | 其他业务、仅候选适用业务覆盖正式版、把共享知识复制成多条 |
| source | 该Source及其Job、原始资料、观测、情报、反馈 | 自动访问转入的Work或正式知识 |
| raw_asset | 该资料及其定位证据，processing派生资料沿父链取权限交集 | 同批其他资料、其他作品 |
| work | 该Work下单元、材料版本、输入集合、报告、评价、预测 | 未授权上游资料、其他作品及跨作品引用 |
| knowledge | 该稳定知识条目及动作允许的候选／正式历史版本 | 无审状态下正式检索、上游原文、其他关联知识 |
| standard | 指定标准及其版本 | 编辑模型连接、发布其他标准 |
| file | 指定文件独立下载；文件必须accepted | 任一引用它的业务正文，未经验证的文件 |
| task | 该任务的安全状态与获授权管理动作 | 输入正文、模型原始输出、请求凭据、超出任务权限根 |

派生内容含有原始证据时，需要本体动作许可和实际引用依赖的evidence.read／file.read许可；业务角色只允许看到正式知识，不会因此自动获得原视频权限。文件通过父对象访问时先验父对象，再沿明确file_id引用检查file.read在该父范围或file范围上的许可；同一物理文件被别的对象引用不扩大权限。S05.3新增file_intakes作为上传接收的明确Work→File关联；材料历史仍按精确ArtifactVersion.file_id校验，intake文件不能换作品引用；下载每个后续分块重验授权，详见[文件服务](文件存储与访问.md)。直接文件ID访问只接受file范围或org范围file.read，不能猜某个有权父对象绕过校验。

知识、报告或摘要在包含不可读来源正文时不能以“仅隐藏证据链接”保留泄漏文字：正文、摘要、搜索命中及数量先按完整依赖过滤；若允许显示受限占位，仅显示安全状态，不暴露标题或正文。独立报告某些部分可拆分授权的细粒度策略后置，B1按整份输出的全部输入依赖取交集。processing生成资料沿parent_raw_asset／parent_artifact_version追到冻结输入，禁止伪装成用户上传；父链须无环，B1单链深度上限32，超出返回PROVENANCE_DEPTH_EXCEEDED而非放开权限。来源状态事件按event_no顺序解释，来源过期是可信度警告，不自行删除知识；来源撤回／访问撤销则重新检查原文访问，必要时过滤依赖内容，记录影响。

列表、关键词／向量搜索、统计、历史、缓存、文件代理和导出共用同一鉴权谓词；分页及计数在过滤之后执行。历史版本按当下授权读取，不使用生成时权限快照。共享知识当前业务过滤必须依据请求的正式发布版本，候选业务标签不能扩大已发布版本可见性。

### 3、撤权、系统任务与缓存

organizations.authz_version为组织级授权世代，正整数从1开始。成员停用、Grant创建／撤销／到期策略变更、角色动作修改在短事务内锁定组织行，修改并递增世代。读请求、文件流建立和导出生成时读取当前成员及有效Grant，缓存键必须含org_id、member_id、authz_version、当前业务、动作与对象版本；TTL不能代替expires_at即时比较。来源访问撤销／恢复、文件校验状态影响访问、正式发布指针变动及影响可见性的业务范围变化，也须在同事务推进authz_version，避免依赖缓存继续暴露旧内容。会话缓存不得成为权限真相。

写请求在开始及生效前重新检查，普通生效事务用组织行共享锁，撤权及任何需要推进authz_version的事务（包括正式发布指针、来源访问及文件访问状态变更）从事务开始即取组织行排他锁，禁止先取共享锁再升级，使先后有明确提交次序：撤权先提交的操作不能随后发布；生效先提交的记录仍留档，但撤权后的读取必须受限。长网络、解析和模型调用不持有数据库锁；其结果提交时再次鉴权及校验输入，撤权后不发布正式产物，外部已发出的请求无法追回但后续请求停止。

定时采集不是无权限系统账号：collection_plans.authorized_by记录最近明确授权此计划的成员，计划每次执行按该成员当前collection.run、来源及连接状态重新检查，tasks.requested_by及execution_authorized_by也填该成员。成员停用、授权到期或计划停用后不再发新请求。内部清理／索引等确定性维护允许requested_by=NULL，但必须有已登记处理器与权限根，不得据此调用付费供应商、创建人工审核或绕过正式发布规则；生产系统ServiceAccount仍后置。

## 二、任务、取消与重试状态

### 1、任务事实与业务结果

任务保留requested_by原发起人，以及execution_authorized_by实际执行授权人。仅能research.submit的编辑可创建queued待分析；有research.run的成员确认执行后填execution_authorized_by，worker才可领取。自动可执行任务由具备对应动作的发起人同时作为执行授权人。执行前和生效前分别重检原请求仍有效、执行授权人当前动作及全部依赖权限；不能悄悄用管理员身份替用户跑任务。授权执行动作按处理器固定映射：采集=collection.run，文件／文本解析=content.write，分析／质量评价=research.run，知识AI审核=knowledge.review.run，报告AI审核=report.review.run，AI预测=prediction.edit，发布后的外部向量生成=knowledge.publish（同时检验正式发布及证据可读）。固定映射不可由客户端任意指定。确定性无外部调用的内部维护另按第一章限制。

任务state记录执行过程；evaluation／AI结果、材料缺失和报告覆盖范围分别表达业务结果。作品列表按当前材料唯一集数汇总，不把最近一个Task状态当作品状态，也不把重试次数当集数。如下为全部首批合法迁移，未列的迁移均拒绝：

| 当前state | 事件→下一state | 必要条件／原子效果 |
| --- | --- | --- |
| queued | worker领取→running | 校验当前权限、输入、预算和可用时间；锁Task，冻结输入，创建唯一活动Attempt／租约 |
| queued | 前置校验失败→failed | 权限撤回、标准未批准或输入无效，记录失败原因；不发外部请求、不伪造活动Attempt |
| queued | 用户取消→cancelled | task.manage；没有活动Attempt；记录取消及finished_at |
| running | 有效结果提交→succeeded | 当前Attempt持有效租约；结果schema及依赖通过；业务产物、输出关联与终态同事务提交 |
| running | 执行失败→failed | 记录安全错误与Attempt终止；不把供应商错误当空快照 |
| running | 申请取消→cancel_requested | task.manage；保留取消时间，停止后续外部调用，不立即记cancelled |
| cancel_requested | worker确认停止或租约已终止，且均确认无在途外部效果→cancelled | 两种终止路径都要确认无在途外部效果；终止活动Attempt，未提交产物不发布，保留已发生调用和费用证据 |
| cancel_requested | 无法安全停止且超时→failed | 记录CANCEL_UNCONFIRMED或EXTERNAL_RESULT_UNKNOWN，不冒充已取消 |
| running | 租约丢失→failed | 原Attempt记lease_lost；迟到worker无发布权；外部结果可能未知，先留失败再决定是否允许重试 |
| failed | 有限重试→queued | 同输入／配置／逻辑键，权限仍有、失败可重试、预算与次数未耗尽、外部效果已知；追加retry审计，旧Attempt不改写 |

succeeded／cancelled为终态，不回queued；再次主动执行创建新逻辑Task并记录目的。failed→queued必须CAS成功且没有活动Attempt，不能修改冻结输入来伪装重试。原生供应商无法证明某次调用是否发生或是否计费时不自动重发；EXTERNAL_RESULT_UNKNOWN先核验，不能以超时当作免费失败。取消与成功竞争以先取得Task锁的合法提交为准：取消先写入cancel_requested，迟到成功不能发布；成功先提交则取消返回已完成，不撤销已完成结果。

Task.succeeded表示处理器完成约定结果，不等于材料充分、AI通过或知识发布。tasks.business_outcome在succeeded时必为completed或insufficient_evidence；解析／分析完全缺材料可用insufficient_evidence完成并留缺项，不造报告／评级。质量评价证据不足允许独立evaluation结果但grade=NULL；外部错误、解析异常为failed，business_outcome为空。报告partial可以是有效已分析，覆盖缺失明确显示；full报告首批不开放标记，直到S07任务定义明确每种材料的全剧必要输入与判断门槛。

### 2、输入冻结、租约与预算

Task创建事务即固定逻辑输入与task_inputs，并填写inputs_sealed_at；输入关联仅本次未封存事务可写。成功结果与task_outputs同事务写入并填写outputs_sealed_at，failed／cancelled无正式输出关联，不允许同一幂等键换摘要。queued只允许CAS更新执行授权、可用时间、预算或取消等运行控制，并追加独立初评；材料、范围、配置等实质输入纠正一律新建Task／Run，原queued可有权取消。worker第一次领取写inputs_frozen_at作为执行冻结事实，之后执行授权人也不可替换；重试沿用同一输入与配置。提高max_external_calls必须由当前execution_authorized_by本人以该处理器的精确执行动作重新确认新上限，并校验expected_lock_version、当前权限、原请求与Job／Plan上限，记录调整前后值及操作者；其他task.manage持有者不可代为加额。max_attempts提高同样由执行授权人确认，且不扩大外部调用预算。task.manage仅能在已授权预算内取消／重试；如需更换执行授权人，首次领取后须新建Task，不能继承旧授权增加收费。预算调整不是换输入通道。

Attempt以task_id＋attempt_no排序，worker_token标记持有者。提交必须同时匹配最新活动Attempt、worker_token、未过期lease_expires_at、Task期望state及lock_version；失租约后再收到结果只能登记安全失败证据，不能写正式业务产物。数据库时钟判断租约；续租仅当前worker可CAS延长。队列消息重复或延迟不产生第二个活动Attempt。

付费调用按Task.max_external_calls控制总数，默认0，用户／已授权计划显式设置后才能调用；collection_job.max_requests还构成该Job上限，两者取更小值。collection_calls及ai_executions在发请求前登记，所有Attempt累计计数，未知结果也占用预算；AI执行行表示预留一次真实外部调用，不计本地schema校验。调用编号由锁定Task／Job后分配，事务提交后才发网络请求；网络期间不持锁。任务重试不是追加收费授权。max_attempts至少1且显式指定，默认1；S05.4仅对本地暂时错误、超时和无外部预留的失租约配置有限退避，不启用额外采样。

## 三、审核、修订与生效状态

### 1、审核请求与有效决定

review_requests冻结purpose、目标版本及input_sha256；不存一个容易覆盖的“已审核”布尔值。review_heads按(org_id,request_id,reviewer_kind)保存当前有效decision指针及lock_version，AI和人工各一条；review_decisions只追加。没有head表示该类尚无决定。新决定带expected_head及预期head版本，先锁Request，再追加decision、更新head；旧决定永不改写，也不能产生两个并列“最新”。

| 目的 | AI与人工规则 | 生效边界 |
| --- | --- | --- |
| knowledge_release | AI approved后，人工可approved／rejected／needs_changes；人工approved须绑定所见ai_decision_id、同目标摘要 | 满足双审且有knowledge.publish才创建正式发布；管理员同样检查 |
| report_review | 报告AI审核与人工复核分别留档；人工采纳绑定所见AI approved决定 | 只说明该报告复核，不批准报告里的所有知识 |
| evaluation_review | 独立质量评价允许人工直接确认／反驳；AI评价原输出已由evaluation绑定执行，不额外强加第二次AI调用 | 只针对该evaluation，不替代报告或知识审核 |
| standard_approval | 初始专家／人工标注标准由有权成员人工批准，记录定义、来源及适用范围 | 批准后O角色可显式activate；不伪造独立样本验证；效果学习标准仍走B3验证 |

AI error／rejected／needs_changes都不是approved；人工可留下拒绝或待修改说明，不可填AI approved来绕开。AI异常人工强制放行策略尚未产品确认，B1不提供该分支，保留异常并补资料／重试。内容实质修订后创建新Revision及新Request；不将人工新正文覆盖AI已审正文。

知识／报告人工决定若已有AI head都记录所见reviewed_ai_decision_id，批准更要求精确匹配当前approved AI head；AI重评生成新head后，旧人工决定仍可历史查看，但当前视图标记待人工复核，不自动复用。该规则适用于知识和报告，不把evaluation_review／standard_approval不存在的AI head当必需项。人工确认可以由同一个具备授权的人重评，保存supersedes链及理由。UI已有“确认／反驳”映射到approved／rejected，needs_changes表示待补，error保留系统异常。

### 2、知识候选与正式版

候选状态由当前Revision＋Request／Heads推导，首批不额外维护相互矛盾的knowledge.status列：

| 可见状态 | 判定 | 允许的下一步 |
| --- | --- | --- |
| draft | 有Revision，尚未Request | 编辑生成新Revision，或明确送审 |
| pending_ai | 有Request，无AI head | 排队执行AI审核 |
| ai_error | 当前AI head=error | 保留错误、补材料或受预算保护地重试；不发布 |
| needs_changes | 当前AI head=rejected或needs_changes，或绑定当前AI head的人工head为rejected／needs_changes | 新版本修改送审；同版本重新审核需理由与新head |
| pending_human | AI approved，没有绑定当前AI head的人工approved | 有权人工复核 |
| ready_to_publish | AI及人工均对同版本approved且人工绑定当前AI head | 有knowledge.publish权限的用户发布；可与“审核通过”操作同事务，无额外新页面 |
| published | 确切Revision已有KnowledgePublication | 正式浏览；实质修订另建候选，不覆盖发布记录 |

候选状态优先级为published→无Request的draft→无AI的pending_ai→ai_error→有效needs_changes→ready_to_publish→pending_human；绑定旧AI head的人工决定不参与当前状态计算，但保留历史。

正式结果只读knowledge_items.published_publication_id所指的Publication／Revision，标题、正文、分类、适用业务取发布Revision，而非可变identity.title或current_revision。同条知识有v1正式版与v2候选时，v1继续展示，v2只进候选区。切换正式指针须CAS当前knowledge.lock_version，目标Revision必须是本次批准的current_revision；延迟到达的旧审核不能把新版回滚。历史正式版本仍按当前授权访问。

发布后的该Revision审核依据闭合，不允许原地换head来改变其发布合法性；如需重审，创建新候选Revision及Request（正文未变也可写“重新核验”理由），保持旧Publication的证据链。来源撤权立即按第一章过滤读取，不能等待重审。撤销正式知识、回收站恢复及永久删除规则仍属未决生命周期，不在此发明停用／删除分支。

### 3、修订、评价失效与预测

| 变化 | 新判断规则 | 保留的历史事实 |
| --- | --- | --- |
| 材料正文、文件、类型、集覆盖或事实校正改变 | 新ArtifactVersion／InputSet；旧评价相对当前材料标记待更新，重跑新Task／Run | v1原报告、输入及结论不改写，不把历史grade改为NULL |
| 同材料仅追加人工初评 | 不改变首次AI独立输入，可复用同一待分析Task；原初评追加保存 | AI首次评级不读人工等级／倾向性文字 |
| 标准／模型／提示词版本变化 | 新执行绑定新版本；旧结果注明采用旧配置，可选择重评 | 不重算、覆盖历史评价或预测 |
| 补集或单元改名／改号 | 新覆盖生成新报告；以冻结输入与单元显示快照还原旧报告 | 较旧完成批次不得覆盖较新报告入口 |
| 知识正文、来源证据、分类、适用业务或时效等内容改变 | B1保守按实质修订创建新版本并双审，不自定“轻微修改免审” | 原正式版和原双审记录 |
| 来源过期／撤回、成员撤权 | 分别提示可信限制／重新鉴权，任务生效前重检 | 不删除历史引用，不让历史保留变成公开授权 |
| 预测草稿输入、指标、条件或数值改变 | 更新草稿lock_version；既有冻结记录不动，再冻结写新记录及可选supersedes | 原冻结区间、条件、标准、模型和时间 |

预测链为draft(estimable／insufficient_evidence)→frozen→可选retracted事件；insufficient_evidence没有合法数值区间，不能冻结；冻结不等于已发布、已校准。冻结操作锁草稿并校验expected_lock_version、输入和权限后复制全部F字段；客户端不能提供frozen_at，使用数据库clock_timestamp()在写冻结行时取时，不使用事务起始时间假装提前。

第一次事务提交后追加prediction_events.freeze_confirmed（服务端实际确认时刻），成功响应在确认事件提交之后返回；若中断，重试同冻结操作只补确认事件、不重复冻结。确认缺失时记录仍保留但不进入合格盲预测集；补确认采用当下服务端时刻，不能倒填。实际冻结先后比较保守使用不早于frozen_at的确认时刻，并在B3结合平台发布时间可信度／精度验证；时间不确定不宣称事前合格。

预测上下文由服务端记录context_kind与outcome_exposure：已知发布案例、已读互动结果或包含观众反馈的判断为retrospective／observed，不能靠隐藏指标改成盲预测；来源与发布时间不明为unknown；只有无已知实绩、对明确未发布版本作判断才可标prospective_candidate／unobserved。这仍只是候选，B3必须再检查同版本、同口径、同窗口、条件可比、发布前确认及未撤销。retracted只追加事件，不改区间、冻结时间，也不自动创建新预测。

## 四、事务、冲突与交接规则

### 1、统一写入与锁顺序

可变身份／指针写入必须带expected_lock_version，更新条件包含org_id、id和该版本；影响0行返回VERSION_CONFLICT，不静默覆盖。唯一键碰撞且请求摘要相同返回既有结果，摘要不同返回IDEMPOTENCY_CONFLICT。错误名为契约设计代号，HTTP映射和OpenAPI在S05确定；不可见对象返回统一不可访问，不能用冲突信息泄露其他组织数据。

短事务锁顺序固定：组织授权锁（普通写共享；授权／可见性变更从开始即排他）→需要修改的角色／Grant→业务身份行（表名固定序、同表UUID排序）→Task／Attempt→ReviewRequest／ReviewHead→输入／配置完整性检查→不可变产物及审计／指针。只读被引用不可变版本不重复锁；发网络请求前必须结束事务，结果提交另开事务重新走授权和锁顺序。所有处理器和撤权流程遵守同序，死锁只允许对整个无外部副作用事务有限重试，不重复发供应商请求。

知识审核／发布事务锁KnowledgeItem后锁Request／Head，比较当前版本、目标摘要、AI／人工head及预期head版本，写publication、更新正式指针、写审计一次提交。Request输入不变，Head仅由追加决定事务更新；supersedes必须是同Request同reviewer_kind的当前head，拒绝分叉／自指。首个head用唯一键抢占，后到请求重新读到冲突，不覆盖先提交决定。

人工批准保存绑定的AI head；AI异步结果只有expected_ai_head和目标摘要仍匹配时可更新，旧AI执行晚到不替换较新决定。知识已发布后不更新原请求head；report／evaluation重评按supersedes追加，历史复核与当前复核分开。

标准激活锁Standard并校验expected_lock_version、同父Revision、当前standard_approval人工head=approved及其摘要；首个版本无有效批准保持active_revision_id=NULL，分析不能自动选未批准候选。B1激活后的批准Request也固定Head，修改或重新评审须新建标准版本，不能改变既有批准依据使历史分析瞬间换标准。standard_revisions.origin_kind明确expert_baseline／manual_configuration／learning_candidate，并留provenance_note；来自学习链的候选不能由客户端改标为人工配置。B1的rubric激活只接受尚无已启用版本的专家基线；已有rubric的新版本及所有learning_candidate启用／回退均依赖B3独立验证，不用初始审批路径绕开。非rubric的提示词／解析模板等配置版本可按人工审批激活，但不得宣称已经效果验证。明确版本的旧分析继续使用其冻结标准，不被active指针变化污染。

### 2、情报转研判及重复提交

跨日采集保留原Job业务日，但live响应若实际captured_at已跨上海日，须DATE_WINDOW_MISMATCH而不写原日快照；除已实测真正as-of能力外，不能将晚执行当历史回补。

交接必须先读用户选择业务／日期的确切SnapshotEntry，校验快照观测、来源证据、可用文件、所选Work和材料类型；同名作品要求稳定ID确认，不按标题自动合并。原情报业务与用户确认的研判业务分别保留：如有权更正为另一业务，目标Work必须属于确认业务，交接同时通过原Source与目标Work权限；两边有任一无权即拒绝，不能静默跨业务。选填集数只适用AI漫剧，未知不补第1集。

情报交接按当前Demo已有校验要求人工S／A／B／C、确认业务和非空题材，并至少选择一个学习点标签或填写具体学习点；AI漫剧还需确认作品名称／稳定ID，名称最长100字，集数为可选正整数且当前集数不超过已知总集数。依据Demo源码researchIntakeForm及提交校验，不新增表单字段。材料不足无法形成真实人工判断时先补材料，不能为满足表单捏造低等级；上传／文本资料接收可以先落RawAsset而不强建初评，后续对应入口的必填按Demo及需求细化。

research_submissions、preliminary_assessments及材料版本／来源关联冻结本次证据、反馈ID、初评、作品名、总集数和当前集号；所有引用均指不可变快照，反馈不存在则NULL，不补今日评论。使用引用冻结而非复制可变实时结果，历史查看仍重新鉴权。请求幂等键复用且摘要一致返回原Submission，不再追加初评；用户主动再次提交新请求键可追加新初评。

锁Work及同导入身份后查import_key／材料版本：相同来源同版本且已有queued Task，复用该Task、追加本次Submission／初评并默认展示最新初评，不增加材料数；有running Task时同输入仍复用并保留新初评，输入不得改变。输入发生实质变化，新建版本和Task，旧queued Task可按有权取消流程取消，原Submission始终可追踪；已有succeeded／failed／cancelled则主动新提交创建新Task，新报告不覆盖旧报告。import_key只识别稳定来源身份及材料用途，input_sha256才表达具体版本与配置，不能把两者混为标题唯一。

分析已启动时，后追加初评只能作独立历史／复核信息，不冒充本次AI原输入；是否向报告展示“本次／其他初评”按其Submission与冻结输入／提交时间关联。报告入口采用Work.report_generation单调代号：创建新AnalysisRun的事务在Work锁内递增，analysis_run立即复制其generation，不等worker领取才分配；重试不换代号。报告成功时只有generation仍是当前代号且primary材料版本仍对应当前材料输入，才能更新latest_report_id。主动重跑历史材料也只进历史，不冒充当前材料报告；较早批次即使晚完成也只进历史，失败新批次不清空已有报告入口。列表保留已有报告与当前任务同时显示。

### 3、冲突处理与不可生效情形

| 条件 | 服务端结果 | 允许恢复方式 |
| --- | --- | --- |
| 编辑／冻结／发布时lock_version过期 | VERSION_CONFLICT，整个事务回滚 | 重新读取并明确提交新版本 |
| 同幂等键但不同摘要 | IDEMPOTENCY_CONFLICT | 使用新逻辑操作键，不覆盖旧行 |

| 权限失效／跨范围／依赖不可读 | ACCESS_DENIED（对外不暴露不可见目标） | 恢复所需授权后重新提交 |
