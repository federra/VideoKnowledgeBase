## 一、设计依据与覆盖范围

依据：[AGENTS](../../AGENTS.md)、[PRD](../AI知识库产品需求文档_PRD.md)、[DESIGN](../DESIGN.md)、[四模块交互](../四模块交互架构.md)及四份模块文档。按用户最新局部截图采用浅灰／炭黑画布、中性灰边框、橙红选中态、胶囊筛选与圆角卡片；中文统一无衬线字体，右上角可切换深色主题。桌面固定左侧四入口，顶部下划线Tab二级导航；窄屏将一级入口收为顶部导航。

包含情报局3个、藏经阁4个、研判室3个、控制台5个二级工作区。信息结构采用 `顶部业务空间 → 一级模块 → 二级工作区 → 页内筛选 → 列表与详情 → 业务操作`。业务空间统一限定情报局、研判室、藏经阁；不代表项目管理。Demo当前实际展示的列表密度、详情形式、字段、状态按钮和操作路径是开发基准；示例权重、评分与固定市场数据不因此成为已验证模型或真实结果。

## 二、可体验交互

- 情报局：情报流沿用顶部业务空间，显示随业务变化的四项演示指标；下方用“榜单／达人”互斥筛选，一次只看一榜。对应的榜单类型或达人多选筛选随之出现，右侧洞察面板仍可收起。宽条目共用标题、中性剧情简介、灰色来源信息、题材与情绪标签、赞／转／评／藏及“研判”入口；两榜分别每页最多10条。业务单选跨三个模块保留，页内仅保留搜索等局部筛选；右下角“闪念胶囊”独立记录并自动保存，右侧历史胶囊可回看；选题卡新增“头脑风暴”，拖入／点击组合后生成一个可编辑演示方向，明确保存才成为选题；人工确认入池、复制/Markdown导出、采用记录。情报局不出现生产环节筛选。
- 藏经阁：按全局业务空间展示正式知识、入库资料、审核队列与回收站；知识浏览按当前Demo的五类知识切换，不恢复已移除的环节筛选；候选修订；预置AI审核通过样例经人工批准后入库；新增候选进入待AI审核；主动删除进入回收站。
- 研判室：内容研判、发布复盘、规律验证及关联内容均按全局业务空间展示；独立资料输入与任务记录、样例质量报告和证据不足、候选提炼、发布记录与版本关联、24小时点赞补录和更正记录、候选规律验证结构。
- 控制台：采集配置集中管理榜单类型、监测达人和来源计划；另有模板/标准/权限只读预览、运行记录及失败重试演示。标准维度与权重仅为结构示例。

推荐评审路径：`情报流 → 转为选题 → 编辑 → 加入待生产 → 交接`；`藏经阁 → 审核队列 → K-033 → 人工核实 → 正式知识`；`研判室 → 发布复盘 → 对账与补录 → 保存快照`。

## 三、演示边界

最初五条榜单视频的标题链接指向公开原视频页面，标题与公开页面对应；新增31条展示测试样例为虚构文案，使用演示作者，无真实视频链接及评论分析。榜单位置、聚合指标、单视频互动数字、剧情提要整理和洞察均为演示，不是实时采集或真实市场分析。页面仅在用户点击已有原视频标题时打开外链，不自动访问外部平台；不上传资料、不调用模型。新增研判停留在待研判，新知识停留在待AI审核。采集调度、真正的AI生成/审核、服务端授权、预测冻结、标准发布与30天自动清理未实现。资料入口暂支持粘贴文本/链接，不支持真实文件上传。完整预测登记、标准验证编辑、知识恢复规则留待后续设计。

业务数据及榜单／达人筛选配置保存在当前浏览器的 `content-ui-v1` 存储中，主题另存为 `content-ui-theme`，所选业务空间另存为 `content-ui-v1-workspace`（测试使用 `content-ui-qa-v1-workspace`）；`?qa=1` 使用独立的测试存储。新增榜单或达人只增加本地筛选配置，不启动真实平台监测。浏览器禁止持久存储时，仅保留本次页面数据。不同浏览器和file/http地址不保证共享数据。版本快照与操作记录仅用于交互演示，不能替代后端审计。

剪贴板受浏览器权限限制时提供手动复制；导出触发本地Markdown下载并记录交接请求，浏览器最终保存与否仍由下载设置决定。交接与人工采用均不等于生产完成。未定义的恢复/永久清理操作不提供按钮。
