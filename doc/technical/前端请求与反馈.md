# 前端请求与反馈

版本：v0.1｜日期：2026-10-17｜范围：S05.5请求基础；页面真实业务数据按S06以后逐页接入。

## 一、代码边界与运行接口

`frontend/src/api/client.ts`维护同源ApiClient、脱敏ApiError与响应解析；`provider.tsx`把客户端接入已有QueryClient，提供useApi／useApiQuery与统一反馈。App只增加无视觉Provider，不新增登录页、菜单或任务面板，不读取Demo数据作为任何API失败后的返回值。页面主体当前仍为显式Demo适配层，尚未消费业务查询hook；本轮验收的是可复用且真实HTTP已验证的请求基础，不宣称页面已经展示真实数据。

类型取自生成的runtime.ts／operations：health、login、getSession、logout、uploadFile、importFile、downloadFile。计划态first-chain操作不挂成可用服务；未实现来源、列表和任务查询不返回假成功。通用get必须传运行时decoder，后续列表仍需按服务实际建立再接入；查询key必须包含业务、对象版本及全部筛选参数。

开发服务器沿用Vite `/api`→127.0.0.1:8000代理；客户端只发`/api/...`同源地址，拒绝跨域／协议相对路径、路径逃逸、反斜杠、片段及控制字符；`credentials=same-origin`、`cache=no-store`、`redirect=error`。健康接口保持独立liveness语义，不作为数据库或worker验收。

## 二、会话、写入和缓存

HttpOnly Cookie由浏览器管理，不由JS读取或写入。CSRF只在ApiClient实例内存，页面刷新后调用getSession恢复；登录参数直接传方法，不进入React Query mutation缓存、localStorage、URL或日志。身份变更开始前清理API缓存、使旧响应失效；同一客户端禁止并发登录／退出及身份切换期间按旧Cookie恢复会话，错误为AUTH_CHANGE_IN_PROGRESS。权限提示actions只作界面提示，不替代服务端授权。

Provider清理只作用于`['api',...]`命名空间，不清Demo存储或其他缓存。查询key含独立客户端实例代号、组织／成员／授权世代与本地会话代号，401／403／404保守阻断当前查询并取消／移除API缓存；明确错误用于反馈，避免移除后自动重查形成死循环。成功getSession或login恢复新范围；旧成功或旧错误响应在读取正文后再核对代号，不可覆盖新身份或注销新会话。这里是响应／显式刷新驱动的边界，不包含跨标签页撤权推送；业务页面后续接入时须先取得当前会话，窗口重新聚焦仍按实际服务重检。

写方法除login／logout外要求调用方显式保留UUID幂等键，版本／计数保持十进制字符串，不转JS number；不默认生成新key、不配置自动重试。uploadFile发原始Blob，元数据进URLSearchParams，importFile发JSON，downloadFile返回Blob；不创建永久文件URL、不把JSON错误下载成文件。401或CSRF失效清除内存令牌；403／404阻断业务读写后仍允许以已保留CSRF直接退出；退出无论成功与否清除本地数据，失败仍向调用方抛错，不能声称服务端已退出。

默认请求截止30秒，可在1毫秒至120秒内显式配置，支持AbortSignal；取消只停止本次等待，不代表撤销服务端写入。写入超时／网络异常／响应损坏等不确定结果提示先核验、保留原提交标识，不能换key盲目重发。新逻辑操作、版本冲突及预算恢复按后续业务规则处理。

## 三、反馈及响应校验

会话与文件按生成类型补充最小运行时形状校验：UUID、UTC时间、大整数范围、accepted、SHA-256；成功业务必须符合request_id＋data信封。JSON损坏、HTML响应、错误文件类型与不合格形状明确INVALID_RESPONSE，不当空数据。错误仅保留已知code、安全字段路径与UUID request_id，页面消息来自本地固定映射，不显示服务器message、HTML、密钥或堆栈。

useApiQuery统一输出loading／success／empty／error／unauthenticated／forbidden／not-found／cancelled；空态由调用方基于该接口真实结构显式判定，不把NULL当零。筛选切换不继承上一条数据，消费Query AbortSignal、retry=false、gcTime=0、staleTime=0；读取可显式refetch，写入不走自动重试。正常／空态／失败／拒权的渲染测试使用测试探针，不把探针当新增产品页面；后续页面按Demo现有反馈位置消费这些状态。

## 四、验证入口与证据

`pnpm test`验证客户端与React状态分支，`pnpm check`包含22项类型断言及lint；`bash scripts/check.sh`核对Demo／接口漂移、构建及前后端工程。`pnpm api:test`单独运行实际TypeScript客户端→真实TCP HTTP→受限应用数据库角色→随机隔离PostgreSQL及私有文件。该命令只在专用15432本地库环境创建随机测试库／角色，自动清理；临时账号和密码存0600文件，传进程环境只有文件位置，不写项目库、不留浏览器账号、不调用付费API。

真实HTTP测试使用Node fetch：测试适配器补浏览器自动Cookie与Origin行为，没有模拟API响应；其余请求／CSRF／解析均走正式TS客户端。覆盖真实Cookie策略、登录、上传、同key回放、字节下载、非法文件、可信主机空白名单拒绝、403／404、空actions及退出后的401。空actions是实际会话数据，不冒充尚未实现的空业务列表。浏览器另实际对照Demo与工程的控制台／运行状态导航，未进行新登录UI验收。

运行命令、过程与最终结果见[S05.5执行记录](../plans/2026-10-17-S05.5前端请求基础.md)。参考[Query取消机制](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)与[QueryClient缓存控制](https://tanstack.com/query/latest/docs/framework/react/reference/classes/QueryClient)，本项目保守策略以上述代码和测试为准。

已知工具轻微限制：隔离验收的初始化事务若在创建角色后提交前失败，可能因二次清理错误残留随机隔离库；已登记待完善，正常验收路径已实际清理，不影响正式请求或项目业务数据。
