# 抖音“微电影”综合搜索榜

版本：v1.3｜2026-10-30。适用故事短片业务线的视频入口；本榜是搜索候选，不称官方热榜、播放榜或点赞榜。上一任务[博主监测](抖音故事短片博主监测.md)的T−7窗口与点赞排序不适用于本榜。

2026-10-26最新验收：已按[同日成功页续采](同日成功页续采与来源证明.md)引用旧页、仅补缺失目标，正式50条视频／50部评论响应／571条有效评论，每部≤15；search SDK初始化首屏API拦截不发送，实际评论按固定接口JSON读取。限频fence跨过截止时刻造成负数sleep已修复，47个缺失评论请求全部200、成功重复0。真实页面50条与新增评论抽屉通过，详情见[最终修复记录](../plans/2026-10-26-三类采集缺口修复.md)；下文旧失败记录按时间保留。

## 一、固定采集口径

关键词“微电影”、视频通道`aweme_video_web`、综合排序`sort_type=0`、不限发布时间；跟随响应`cursor`及上一页`extra.logid`对应的`search_id`，保留平台返回顺序，取最多50个去重后的真实视频。排除图文、广告及非单条视频结果，不自行按赞／播放重排。参考接口资料未说明综合排序的具体权重，结果可能随账号、时间变化；不声称其为固定可复现的官方名次。

`statistics.digg_count/comment_count/collect_count/share_count`映射赞／评／藏／转，验证为非负整数，缺失null。卡片沿用故事短片博主布局，右侧顺序赞、评、藏、转；发布时间按北京时间显示。每视频按接口返回顺序留最多15条一级评论，不抓回复；累计评论数与本地样本数分开，未执行AI分析。

## 二、方法与参考资料

参考[MediaCrawler客户端](https://github.com/NanmiCoder/MediaCrawler/blob/main/media_platform/douyin/client.py)、[搜索流程](https://github.com/NanmiCoder/MediaCrawler/blob/main/media_platform/douyin/core.py)、[视频通道及排序枚举](https://github.com/NanmiCoder/MediaCrawler/blob/main/media_platform/douyin/field.py)。其方法是固定搜索接口、会话签名、offset／search_id分页，再按视频ID访问评论接口；仅参考思路，不复制受限许可实现。结合[Douyin_TikTok_Download_API v5.1.7端点](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/v5.1.7/src/dtk/platforms/douyin/endpoints.py)和[参数构造](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/v5.1.7/src/dtk/platforms/douyin/params.py)的固定官方地址与会话一致性要求；未新增第三方签名源码到产品。

搜索仅允许官方`/aweme/v1/web/general/search/single/`及`/aweme/v1/web/search/item/`，评论仅`/aweme/v1/web/comment/list/`；参数须精确匹配关键词、视频通道、综合排序及当前游标。先由独立已登录会话触发站内SDK搜索接口，后续分页用同一会话的站内XHR；评论通过对应视频页SDK的接口JSON，必要时跟随首屏评论游标。**不使用截图识别、OCR、页面卡片文本或滚动取数。2026-10-26人工验证后，已有同会话首屏16条真实接口JSON离线解析成功；无人值守分页与完整评论仍待验。**

独立会话使用已有`data/douyin/browser-session/profile`，不依赖日常Chrome前台。Cookie和完整签名URL仅在会话内存／私有profile；证据只留固定接口路径、必要业务参数和响应JSON，不输出认证头。登录过期可能需要维护独立会话，不声称永久免费方法永不失效。

## 三、限量、异常与证据

来源能力`douyin.search.microfilm`，版本`douyin-microfilm-search-v1`，任务`collect.microfilm`。最多10个搜索页、50视频、每视频最多2个评论页但最终≤15评论。安全预算112单位，**单位为页面访问或显式XHR，不等于112次实际HTTP**；页面可能自动请求SDK初始化详情。评论页仅放行该视频一次详情初始化，不读取其正常响应为业务证据；初始化403／429同样立即阻断新请求并落24小时冷却。页面／显式XHR串行至少10秒，访问前校验权限、租约与上海日期；无身份轮换、免费API、无模型调用。

用户本轮明确允许新搜索“失败后再试一次”：冻结输入`one_off_retry=true`，全批失败计数最多2次，重试仍用同一会话；它是一次新搜索批次的有界例外，不清除原博主冷却、不授权其他来源或后续批次无限重试。默认UI刷新及CLI不带该标记，遵守现有冷却。每次操作预留账本，成功／失败原包均持久保存；嵌套JSON异常不能覆盖已取得的响应。解析后页无效时保留已验证的前缀；样本不足或评论未取到明确保留缺失，不伪造50或15。

业务快照按上海采集日封存；任务／调用／原包／评论均有来源关联。读取限定本能力最新榜单，其他故事短片board不得混排或触发本榜错误；评论抽屉读取确切快照任务的manifest及原包，不在GET中采集或分析。采集来源完成或失败后均暂停，通用worker／sweep不启动该任务，无新增表或迁移。

显式命令：`backend/.venv/bin/python scripts/collect_microfilm.py`。仅当用户再次明确授权新批次的一次补试时，才使用`--authorized-one-retry`；不能把本轮已消耗授权当长期配置。常规“重新采集”已接该渠道，默认不启用补试例外。
