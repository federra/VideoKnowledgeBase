## 一、业务边界

三条业务线为 **AI漫剧、故事向AI短片、电商短视频**；各自经过 `选题 → 脚本 → 资产 → 成片`。知识和评价可跨业务复用，具体适用范围由业务线、环节、对象类型、任务与平台标注；不建设12套独立知识库或页面。分镜脚本归脚本，分镜图／预演图归资产。

知识库首期提供情报、选题卡、知识加工与浏览、内容评价、发布效果复盘。剧本、图像、视频的正式制作和发布由外部工具完成。已立项／已发布内容在本系统只保留轻量标记、内容版本与发布记录，不引入项目工作台、人员排期或制作流程管理。

长期可向生产系统提供项目上下文与动态知识包；**项目空间、自动组包、生产系统接口及生成记录回传均属后置能力**。首期选题由用户复制或导出交接，评估与复盘不依赖生产系统接入。

## 二、四模块职责与交接

| 前端入口 | 首期职责 | 对其他模块的交接 |
| --- | --- | --- |
| **控制台** | 配置监测源、采集计划、解析／拆解模板、模型、评价标准、权限；查看任务运行 | 向另外三模块提供配置及版本，不承接用户每日选题或评价操作 |
| **情报局** | 浏览采集信息与原链接；人工判断是否值得研究；AI生成选题卡；用户手动记灵感、编辑确认选题 | 有研究价值的原内容进入研判室；确认选题进入待生产选题池 |
| **研判室** | 接收情报转入、上传或粘贴链接；多维分析、质量评价、发布前预测；采集／补录发布数据，复盘、提出与验证候选规律 | 候选知识送藏经阁审核；验证通过的评价标准进入控制台共用版本库；可把分析结果回显情报局 |
| **藏经阁** | 浏览、检索、人工新增、编辑审核正式知识；管理版本和回收站 | 接收研判室的候选知识；已审知识作为用户学习及研判参考，后续可供生产系统调用 |

交接以来源ID、内容ID和版本引用建立关系。情报、选题卡、研判报告和知识条目是不同对象；同一原始信息可供多条流程使用，不为每个入口复制一份无法追溯的资料。

控制台是配置入口。每日工作中，用户不需要在选题、浏览知识或研判前反复配置。情报局的“值得研判”是研究意图，不等于“内容优秀”或正式评价；失败案例也能进入研判。用户可以直接确认选题，无须先完成研判；研判报告也不必每次都转成知识。

## 三、三条完整工作主线

**1、情报选题：** `监测源定时采集 → 榜单／信息展示与原链接查看 → AI生成选题卡及评价／用户手动记录灵感 → 人工编辑确认 → 待生产选题池 → 首期复制或导出交接`。用户还可在情报信息上作初筛并标记待研判，情报局将来源、内容版本及研究意图交给研判室。选题池只收已确认选题；草稿、被忽略条目与交接记录分别保留。

**2、内容研究与知识沉淀：** `情报转入／用户上传／粘贴链接 → 解析视频、文本或图片 → 多维评价与详细分析 → 可选提炼规则／知识 → AI审核 → 人工审核 → 藏经阁正式知识`。研判可独立结束；低表现内容可沉淀失败案例。只有原始证据足够时才给出相应结论，不能仅凭标题假装分析全文。藏经阁也支持人工新增知识，仍须经过审核。

**3、自有内容发布验证：** `对待发布内容版本评价并冻结表现预测 → 外部立项／制作／发布 → 用户粘贴发布作品链接 → 关联内容版本 → 自动提取可得实绩或人工录入 → 预测与实绩对账 → AI提出偏差假设、人工复盘 → 候选知识／判断标准 → 验证审核 → 生效并供下一轮使用`。已看到结果的历史案例仍可复盘，不能被算作发布前盲预测。若最终成片与事前评价对象实质不同，须关联新版本并在发布前重新判断。

发布链接采集按平台能力逐个适配，目标数据包括转发、评论、点赞、收藏；可获取时增加播放量等统计基础，并记录平台、账号、发布时间、采集时间、观察窗口和数据来源。自动提取失败或缺项允许人工补录，缺失不按零处理。每次采集形成快照，不把多次累计量相加，也不以较晚累计值替代较早窗口的数据。

## 四、评价与学习闭环

质量评价、市场表现预测和实际表现分别保存。选题卡的嵌入式评价与研判室复用同一评价能力；对不同版本或新增分析维度生成相应评价记录。Rubric（评价标准）按业务线、环节、对象类型适配：选题看热度、人群与可执行性；脚本看钩子、冲突、节奏；资产主要看一致性、质量与真实性；成片看叙事、声画、表达与规则。资产质量不直接等同市场增长预测。

对账须锁定**同一最终作品版本、同一指标口径、同一观察窗口及可比的发布条件**。预测保存标准／提示词版本、理由与服务端冻结时间；作品发布后补写的判断不能成为盲预测。未预测、放弃、低表现内容也保留状态，以免只从成功作品提炼规律。

更新判断模型的首期含义是迭代 **评价标准、规则适用条件、参考案例、评价提示词**；不默认训练新模型。路径为 `预测留档 → 实绩对账 → 偏差假设 → 候选版本 → 新旧标准回测／独立样本验证 → 人工审核 → 启用或保留旧版`。单条案例只产生假设；样本不足时维持候选。新标准生效不改写旧评价和预测，可追溯并支持回退。

候选知识及事实规则进入藏经阁的AI和人工审核链。正式知识可人工修改、新增或删除：实质修改形成待审版本；删除进入回收站，**30天后自动永久删除**。知识有效期、待复核、停用、归档和恢复等生命周期细则仍待讨论；到期不自动等同删除。

## 五、数据对象与技术承载

首期最小关联链：`Source／RawAsset → TopicCard或ArtifactRef版本 → Evaluation／Prediction → Publication → Performance快照 → Review／ValidationRun → KnowledgeItem或Rubric新版本`。TopicCard为选题卡，ArtifactRef为轻量内容档案，二者可关联；Publication记录每次外部发布，同一作品允许多次发布。Performance保留指标定义、窗口、数值与自动／手工来源。知识条目通过Relation保留来源证据与案例关联。

后台按职责复用五类能力：**来源采集与解析、情报与知识加工、评价与预测、发布复盘与学习、基础对象与治理**。这些是逻辑模块，不要求分别部署。监测计划与评价标准由控制台管理；内容生成模型路由与生产流程不在本系统内。

结构化对象及关系可由PostgreSQL／JSONB承载，pgvector加全文检索用于知识召回，对象存储管理原始资料与素材；异步任务处理采集、解析、评价和重试。此处为技术建议，具体选型与指标在实施设计中确定。

后置对象包括 ProjectContext、TaskServiceConfig、KnowledgePack、ServiceCall、GenerationRun 等，与生产器接口明确后再设计。现阶段内容ID、版本、来源和发布关联先行建立，以便后续对接。
