# 同日成功页续采与来源证明

版本：v1.0｜日期：2026-10-26。对应故事短片博主和微电影缺页修复；不改变前端或开启调度。数据库增量0026_page_resume不新增表列。

续采入口为`app.collection.page_resume.start_resume(engine, principal, original_job_id, key=..., raw_ids=None, connector=None, connector_factory=None)`；`submit_resume(connection, ...)`仅建任务，返回`task_id, source_id, handler`，供外部显式Runner执行。博主调用方须先打开SessionPosts上下文再通过connector传入；微电影由处理器打开connector_factory。固定任务种类collect.creator-posts.resume／collect.microfilm.resume，handler_version保持原连接器版本，任务与新Job使用原source／connection／business／date／capability／version／safe_request及原预算。执行完成或失败后恢复来源暂停；queued／running保留运行状态。

原Job须已failed或succeeded；只接受同源同日、HTTP200且outcome=success、API origin、原call/job归属一致、正文SHA吻合的不可变raw。输入引用使用task_inputs.role=collection_page_reuse；独立manual manifest固定原Job、raw ID及SHA，不复制原响应。冻结阶段重新核对权限、当前来源／连接配置、主页身份与时间窗；原文与冻结引用均参与input_sha256，执行／心跳／发布沿用Runner校验。

视频搜索页须从offset0连续且search_id一致；博主页须从cursor0连续。评论须绑定冻结搜索结果中的视频、从cursor0连续且每视频至多15条。raw_ids未显式传入时，使用原任务的已引用成功页及自身成功call原文，并加入当前同源同日最新microfilm_manifest所指成功评论；不用物理历史评论行推算当前样本。传入raw_ids时顺序为全部连续搜索／作品页，然后按视频cursor顺序的评论页，不允许成功请求摘要重复。

命中冻结成功页时直接使用原值，发生在collection_calls预留之前；该步骤不产生网络请求、新call或新API raw。只有实际缺页发请求并写新任务自己的真实调用账本。新快照引用原始raw及已有不可变观测ID；已有评论证据也保留原ID。重复解析字段不一致即拒绝。数据库cip_page_reuse_allowed仅放开原包与新快照Job不相等这一处，限制固定任务种类、同源／同配置／同日、封存输入、原HTTP200成功call及冻结SHA；新Job仍必须有至少一条真实成功collection_call，不能把纯重放伪装成新采集。

同一0026另收录红果精确人工HTTP导入guard，方法hongguo-saved-http-v1、collect.hongguo.saved、hongguo_saved_capture、固定四榜、零外部预算／零call、提交人、同日真实采集时间、完整HTTP200及SHA须同时匹配。HTML使用Base64信封保存原UTF8字节，保留真实NUL而不伪造正文；该例外不适用于普通manual资料。细节及验证由红果超时修复记录承接。
