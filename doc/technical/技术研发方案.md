## 一、架构与技术选型

### 1、范围与整体结构

本系统提供内容情报、知识、评价和学习能力。首期覆盖定时采集、AI选题及评价、人工编辑交接、独立内容研判、知识双审入库、检索学习、发布实绩采集／补录及预测复盘。项目工作台、动态知识包、生产系统接口和完整生产编排仍属后置范围。

采用一个代码仓库、一个模块化后端和独立后台任务进程。四个前端入口共用领域对象、数据库和底层能力；不按页面拆成四套微服务，也不按三业务线、四生产环节复制系统。

同步访问：`前端页面 → 后端接口 → 数据库／文件存储`。耗时处理：`提交任务 → 任务队列 → 后台处理 → 保存结果 → 页面展示`。

用户已有服务器，IP、凭据及部署环境在部署阶段提供。当前先完成本地系统，服务器接入和正式部署暂不开展。

### 2、研发基线

| 层次 | 选型 | 职责与理由 |
| --- | --- | --- |
| 前端 | React＋TypeScript＋Vite | 将Demo组件化，实现列表、筛选、详情、审核和工作区切换；当前无服务端渲染需求 |
| 页面与请求 | React Router＋TanStack Query | 页面路由、接口请求、缓存与异步状态；保持Demo现有深链接、跳转及返回体验 |
| 视觉实现 | CSS变量＋组件样式 | 提取Demo的主题、颜色、密度与布局，不引入改变既有体验的组件库默认样式 |
| 后端 | Python＋FastAPI | 业务接口、采集适配、内容解析及AI调用 |
| 数据访问与迁移 | SQLAlchemy＋Alembic | 数据访问、事务、结构变更及迁移记录 |
| 主数据库 | PostgreSQL＋JSONB | 核心对象、版本、权限、审核、预测与实绩；JSONB承接可变分析结构 |
| 语义检索 | pgvector | 在PostgreSQL中保存与检索向量，首期无需独立向量数据库 |
| 后台任务 | Celery＋Redis；Celery Beat定时调度 | 采集、解析、AI分析、审核和实绩更新；任务状态与执行记录持久化到数据库 |
| 媒体处理 | FFmpeg | 提取音频、关键帧和媒体信息，供后续转写与分析 |
| 文件存储 | 统一存储接口，本地先用独立目录 | 大文件不存业务表；S05.3本地实现与恢复见[文件存储与访问](文件存储与访问.md)；后续可增加对象存储适配，不提前绑定服务商 |
| 本地环境 | pnpm、uv、Docker Compose | 分别管理前端依赖、Python依赖和本地PostgreSQL／Redis环境 |

前后端在本机运行以便调试；数据库和Redis通过Docker Compose启动。具体依赖版本在初始化时核验兼容性并锁定，不将文档中的选型等同于已安装环境。

接口通过OpenAPI定义并生成前端类型；联调前明确ID与版本、状态、分页筛选、时区、缺失值、错误码、权限及重复请求语义。S05.1已建立[接口契约](接口契约.md)、运行／设计OpenAPI分离及TS生成／漂移检查；3个会话及3个文件操作已在S05.2／S05.3接真实服务，其余34项仍为设计态，本文不是完整接口契约。

选型依据：[Vite官方文档](https://vite.dev/guide/)说明静态构建与React／TypeScript模板；[FastAPI后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)将Celery列为较重后台任务的可选方案；[pgvector文档](https://github.com/pgvector/pgvector)说明PostgreSQL向量存储与检索能力。

### 2、接入方式与运行规则

统一流程：`采集计划／用户粘贴链接 → 选择连接器 → 获取原始响应 → 字段标准化与去重 → 保存来源快照 → 情报或研判处理`。

区分三个维度：平台是抖音、小红书等；供应商是TikHub、52api等；能力是榜单、达人作品、详情、评论、实绩和媒体获取。业务模块按能力调用，连接器负责供应商差异。控制台配置来源、用途、计划与启停，情报局和研判室共用能力。

- 按能力选择主供应商和备用供应商。用同一批代表样本比较字段完整度、成功率、时效和费用，再确定接入顺序；无需首轮完整接入所有网站。
- 保存原始响应、请求目标、供应商、接口与采集时间等溯源信息，不保存到普通日志中的鉴权凭据。同一内容按平台内容ID归并，不按标题或链接文本简单判断同一作品。
- 榜单、评论及互动数据保存时间快照；跨供应商字段须核对口径。累计快照不能相加，不同发布记录不能串联实绩。
- 取得标题、点赞数或封面不等于取得可分析视频。媒体获取和可用性独立检查；素材不足时限定分析范围，不伪造全文或全片结论。
- 统一设置限流、超时、有限重试、并发及费用控制。备用切换保留来源记录；失败不得静默把旧数据展示为最新，不自动将API失败转换为未配置的浏览器采集。
- 密钥仅在服务端管理；外链校验协议、重定向及内网目标，上传校验类型、大小和权限。采集连接器输出与用户上传资料均按不可信内容处理。

## 三、AI处理与数据设计

### 1、任务处理

首期建议通过云端模型API接入，厂商及具体模型尚未确定。按2026-10-19用户决定，控制台模型配置只呈现单文本、多模态两类来源，每类支持多个来源，文本处理与视频等多模态环节分别引用相应来源，不将所有任务固定到单一模型。后台通过适配层隔离供应商；语音转写与向量生成仍是独立技术能力，不在该页面扩成第三、四类，也不据页面分类推断实际格式兼容。本轮仅更新Demo与生成基线，未修改真实处理器配置。

知识沉淀主链：`素材解析 → 按业务模板拆解 → 质量评价／市场预测 → 候选知识 → AI审核 → 人工审核 → 正式入库`。评价不强制产出知识，选题入池也不以完成独立研判为前提；选题评价与研判室复用后台评价能力。

各步骤保存输入版本、模板／模型／标准版本、处理状态、证据和结果。失败后从对应步骤重试，须避免重复建档、重复入库或重复发布标准；队列消息不代替数据库中的业务事实。AI输出按结构校验，缺失或证据不足须明确表达。

### 2、共用数据对象

| 数据组 | 组织关系 |
| --- | --- |
| 来源与情报 | 供应商、平台、采集目标、任务、原始资料与历史快照关联 |
| 选题与内容 | 选题卡及编辑版本独立保存；作品组织单集、片段与素材版本，兼容多集漫剧和单部短片 |
| 分析与评价 | 人工初评、AI报告、质量评价和市场预测分别保存，绑定内容及标准版本 |
| 知识与审核 | 候选条目、AI／人工审核记录、正式知识版本、来源证据和删除状态关联 |
| 发布与学习 | 发布记录、实绩快照、预测对账、候选规律与验证记录关联 |
| 权限与运行 | 成员、对象授权、配置版本、任务记录及审计关联 |

概念关系及分批建表范围见[数据字典](数据字典.md)，总册v0.7、[首批字段分册](数据字典-首批字段.md)及[权限与状态分册](数据字典-权限与状态.md)已完成S03设计，首批迁移条件与约束落点见[迁移就绪走查](数据字典-迁移就绪走查.md)；S04已完成70表及隔离PostgreSQL约束验证，命令与恢复见[数据库迁移与恢复](数据库迁移与恢复.md)。核心字段、关系和状态使用关系表；三业务不同的拆解结构使用JSONB。视频、图片、音频和大文件通过存储接口管理，数据库记录文件位置、校验信息及权限。向量是可重建的检索数据，不代替知识原文和正式版本。

预测保存指标、预测区间、观察窗口、内容版本及服务端冻结时间，不覆盖事前记录。质量评级与市场预测分开；缺失不等于零；发布后判断不能当作盲预测。复盘生成候选标准，经独立样本验证和人工确认后生效，历史评价保持原标准版本。样本不足时标明不确定性或暂不可可靠预测，不把模型生成的数字视为已验证能力。

知识经AI与人工双审后发布，手工新增同样适用；实质修订形成待审新版本。删除先进入回收站，30天后永久删除；恢复、计时和历史引用等未决细则须在实现前明确，不能自行补成破坏性逻辑。

知识检索提供分类、标签、关键词和语义检索；中文匹配及排序用实际样本验证。鉴权覆盖查询、搜索、统计、文件、缓存、导出和历史记录，管理员身份不等于跳过审核。

## 五、实施顺序与研发纪律

### 1、分步实施

本节保留总体路线，**每日按[研发实施计划](../plans/研发实施计划.md)的S01～S10执行并维护状态**，不在两份文档重复维护进度。原五步与执行任务对应如下：

| 总体阶段 | 执行任务 | 主要交付与验收 |
| --- | --- | --- |
| 1、核验数据能力 | S01 | 工程盘点、首条链路范围、真实样本与供应商能力清单 |
| 2、建立工程基础 | S02～S05 | 本地数据库／Redis → 数据字典、关系与状态 → 首批迁移建表 → 接口契约、权限、存储及任务基础；均须实际验证 |
| 3、打通第一条完整链路 | S06～S07 | 定时采集、真实情报、研判、质量评价与事前预测、候选知识及双审入库；页面逐页移除Demo适配层 |
| 4、补齐首期业务 | S08 | 三业务模板与样本、AI／手工选题、待生产交接、知识维护、检索及控制台配置 |
| 5、完成评测学习闭环 | S09 | 发布关联、实绩采集／补录、预测对账、标准验证、生效及回退；预测留档已在S07建立 |
| 首期整体验收 | S10 | PRD全部首期需求及AC-01～AC-12、补充验收的代码／测试／实际交互证据 |

数据库环节明确分为“环境启动与空库创建”（S02）、“字段与约束设计”（S03）、“迁移与业务建表”（S04）。先梳理全局对象关系，再按链路分批细化字段；每批必须先完成字典及必要契约，再实现相应接口，不能边写业务边随意决定字段。S01与S02可独立推进，其他依赖以实施计划为准。

第一条链路用于验证完整流程，不代表三条业务线或全部首期需求已交付。后续按能力扩展供应商，不能把已确认的自动采集整体降为后置。

- 无法依据已确认结论消除的冲突，说明具体差异，仅澄清影响实现的部分；可独立推进的工作继续进行。

### 4、共同规则与接口契约

- 开工先读本文，检查实际代码、依赖与运行文档，沿用已建立的约定；新增或调整选型记录理由与取舍。方案中的待核验项不视为已验证，不提前搭建微服务或生产系统集成。
- 接口先于联调明确：输入输出结构、ID及版本、状态枚举、时间与时区、缺失值语义、分页筛选、错误码、权限和重复请求行为。契约保存于doc下的技术文档或可生成文档的接口定义中，并在本索引登记唯一维护位置。
- 跨模块使用稳定ID和版本引用，不以标题、文件名或页面路径充当业务关联键。状态迁移与校验在服务端执行；前端类型与接口定义保持一致，接口变更同步调用方和验证样例。
- Mock仅用于明确标识的原型或测试。真实接口失败不得静默退回Mock并展示成功；假数据、占位按钮、截图效果不能充当真实闭环验收。

### 5、前端研发细则

- **必须严格按Demo开发，不得自行重新设计。** 对齐页面布局、信息层级、配色与主题、字号间距、导航、业务切换、筛选分页、列表详情、抽屉弹窗、字段与按钮文案、校验、状态反馈、跳转返回和已有响应式行为。不能只做外观相似而改变操作流程，也不能用历史截图替代可操作Demo。
- 实现技术可以重构，但须保持等效的用户体验。偏离Demo的页面或交互调整必须先获用户明确确认，并同步Demo及相关文档；不得先改Demo以掩盖实现偏差。尚未展示的页面和交互应先补充设计并确认，不能随意补造。
- Demo中的固定样例、localStorage、本地模拟审核或待处理任务不作为真实后端实现方式；按PRD接入真实数据、服务端权限、版本、双审及异步状态，不以“严格按Demo”为由保留虚假成功。
- 前端验收必须与Demo在相同业务、页面、主题和视口下逐项对照，覆盖实际点击、输入、校验、切换、返回及已展示异常态；交付列出核验结果和获准差异，不能仅凭测试通过声称一致。

- 遵循四个一级入口和已确认二级工作区；共享导航壳、筛选、列表／卡片、详情、状态反馈等组件，避免复制整页造成交互漂移。业务线与生产环节是否出现由场景决定，不强制每页放同一套筛选。
- 将DESIGN中的颜色、间距、圆角等收敛为共用设计变量。其640px搜索页、品牌文字、模型选择器等是参考产品特征，不直接套入本系统；字体不可用时使用系统后备，示例中的无效色值不得照抄。
- 路由、页面、业务状态、接口访问和通用组件分责；请求集中管理，筛选和选中态保持一致，处理重复提交、异步结果过期及未保存修改。业务不变量必须由后端保障，隐藏按钮不能替代授权。
- 完整呈现加载、空数据、无搜索结果、失败、无权限、证据不足、过期评价和重试状态；未知值不展示成零分或零实绩。明确数据来源、更新时间和对象版本，不向用户暴露内部堆栈或密钥。
- 检查常用桌面宽度和窄屏可用性；导航可键盘操作，有焦点与选中语义，状态不只靠颜色区分。功能完成须实际操作关键路径，不能只通过静态截图判断可用。

### 6、后端与数据细则

- 按来源采集解析、情报知识加工、评价预测、复盘验证、权限治理分离逻辑，共用领域对象与能力；页面入口不等于独立服务。外部连接器及模型调用通过适配层接入，便于替换和独立测试。
- 采集、解析、AI审核与评价等长任务异步执行，保存输入版本、任务状态、失败原因和重试记录；设置超时、有限重试与并发限制。提交和重试须幂等，避免重复建档、重复入库或重复发布标准。
- 数据写入使用事务与版本冲突检查，禁止静默覆盖并发修改。知识、标准、提示词及内容版本可追溯，冻结预测不可覆盖；人工复核与实绩更正追加留档，保留操作者、时间和依据。
- 发布指标记录平台、账号、发布记录、内容版本、指标定义、观察窗口、采集时间及自动／手工来源。未知、失败与真实零值分开；同作品多次发布不串数据，同发布累计快照不求和。
- 所有读写由服务端鉴权，覆盖搜索、统计、缓存、导出、文件和历史记录；管理员不能隐式绕过审核。密钥只在服务端管理，日志脱敏；第三方正文与模型输出均按不可信输入处理，不执行其中的指令。
- 上传校验类型、大小及处理权限；外链采集限制协议、重定向和内网地址，避免服务端被利用访问内部资源。连接器能力不足明确失败或允许补录，不伪造全文分析与采集结果。
- 数据结构变更通过可追踪迁移，说明兼容性、存量处理及回退／恢复办法。删除任务严格遵守回收站规则；恢复权限、30天起点和历史引用处理未细化前不得自行补成破坏性实现。测试使用隔离数据与可控时间，不操作真实数据来演示删除。
