## 一、产品定位与职责边界

### 1、目标与阶段

业务覆盖 **AI漫剧、AI短片（故事向）、电商短视频**，适用环节为 `选题 → 脚本 → 资产 → 成片`。三条业务共用知识底座，差异通过内容类型、拆解模板、评价标准与适用标签表达，不建设12套页面或数据库。

首期解决：外部信息难转成可用选题、原始资料难沉淀成知识、内容判断缺少稳定依据、发布经验难验证和复用。首期重点验证选题采用、知识可用性、评价可追溯性与学习闭环；不以知识包采用率或生产系统收益证明首期价值。

后续在生产系统与接口明确后，再增加项目上下文、任务组包、自动调用及生成过程回传。首期保存稳定ID、版本与关联关系，不提前实现项目管理或完整生产接口。已立项、已发布内容在研判室保留轻量立项标记、对应内容版本与发布记录，用于评价和复盘；不承担人员、排期、制作进度管理。

### 2、系统分工

| 能力 | 本系统职责 | 外部工具 / 生产系统职责 |
| --- | --- | --- |
| 情报与选题 | 定时采集、聚类；AI生成和评价选题卡；用户二次编辑与选择；管理待生产选题池 | 使用选定题目开展正式创作；首期通过复制或导出交接 |
| 知识获取 | 情报转研判、上传、链接或手工新增；解析提炼、AI审核、人工审核、入库与检索学习 | 提供原始资料；未来按授权调用知识 |
| 内容评价 | 用户独立提交选题、脚本、资产、成片及参考资料；AI评价、人工复核、版本比较 | 创作、修改剧本及分镜，生成图像、视频、配音和剪辑 |
| 发布前判断 | 记录质量评价与市场预测，冻结对应版本及判断依据 | 决定是否发布并执行发布 |
| 发布与复盘 | 粘贴发布链接，按平台能力自动提取效果；人工补录／导入；关联事前预测、对账复盘、验证升级 | 在外部完成立项、制作、发布与投放，提供发布链接和必要补充数据 |
| 项目与知识调用 | 后置：项目上下文、知识包及调用关联 | 完整生产流程编排、模型选择、执行Prompt、生成参数与创作文件管理 |

本系统可生成选题卡、拆解结果、知识摘要、评价及复盘报告；支持选题卡的人工编辑。正式脚本、分镜脚本、图片与成片的制作、改写和发布属于外部生产工具。**分镜脚本归“脚本”，分镜图与预演图归“资产”。**

### 3、三条业务线与四个环节的支撑

| 业务线 | 选题 | 脚本 | 资产 | 成片 |
| --- | --- | --- | --- | --- |
| AI漫剧 | 题材趋势、受众情绪、爽点、同类案例 | 人物关系、分集结构、冲突反转、节奏与分镜方法 | 角色与画风参考、场景规范、角色一致性 | 镜头节奏、声画、连续性与爽点呈现 |
| 故事短片 | 情绪母题、社会观察、故事命题、受众共鸣 | 人物动机、故事结构、转折、视听表达 | 人物场景、构图光线、视觉风格 | 叙事清晰度、情绪递进、声画和节奏 |
| 电商短视频 | 卖点、用户痛点、消费场景、竞品机会 | 商品事实、钩子、卖点论证、异议处理和转化话术 | 商品参考、品牌规范、演示场景、真实性 | 商品表达、字幕、行动引导、平台规则及转化表现 |

业务线用于全局筛选及对象属性。顶部“业务空间”提供`AI漫剧｜故事短片｜电商短视频`单选，默认故事短片，无“全部业务”；所选业务跨一级模块及二级工作区保留，统一限定情报局、研判室、藏经阁的列表、指标、报告与可关联内容，页面内不重复提供业务选择。共享知识按适用业务标签展示，不拆分知识池。清除页面筛选不改变业务空间；切换空间重新显示该业务数据，新建对象默认当前业务，编辑对象时仍可矫正业务标签。控制台保留跨业务配置管理。该“业务空间”仅表示业务范围，不引入项目工作台、排期或生产编排。生产环节用于知识适用标签与评价任务类型。首期不提供全局项目切换；人物设定、商品事实、参考图等以知识条目或本次评价附件提供。未提供必要上下文时，相关维度标记“证据不足”。

### 4、架构口径

“知识发现、知识服务、评价、知识管理、学习复盘”保留为能力分类，不直接映射一级导航。前端按用户完整任务组织，后台能力由多个页面共用。

与早期业务架构的差异：保留统一知识池、三业务四环节、评测学习闭环和版本溯源；首期将“生产器调用链”改为人工复制／导出与独立内容上传；前端统一为四个已确认入口；项目空间与组包配置不在首期开放。

## 二、用户与完整工作流

### 1、Human User：人类用户

以下矩阵保留长期用户价值，不代表全部能力在首期交付。首期主要服务编剧、编导、视觉人员、运营、主编、知识运营与评测人员；产品人员首期配置采集、拆解和评价，生产调用策略后置。合作伙伴项目共享、客户自助商业化分期讨论。身份不直接等于权限。

| 典型用户 | 核心任务 | 当前痛点 | 系统价值 |
| --- | --- | --- | --- |
| 漫剧编剧 / 故事编剧 | 找选题、写改剧本、查案例 | 灵感分散、案例难复用、方法依赖个人经验 | 提供选题依据、剧情原子、方法、案例和项目上下文，支持外部创作与质检 |
| 导演 / 编导 | 剧本视觉化、设计分镜、控制节奏 | 镜头经验难检索，文字与后续生产脱节 | 提供镜头语言、分镜案例、场景及动作参考，供生产器生成分镜 |
| AI视觉 / 资产生产人员 | 生成人物、商品、场景资产 | Prompt反复试，一致性差，成功经验不沉淀 | 提供角色设定集、视觉规范、参考资产、Prompt经验和质量标准 |
| 电商编导 / 运营 | 找卖点、痛点、写带货脚本、优化转化 | 商品资料与内容经验割裂，爆款经验难迁移 | 聚合商品事实、用户需求、竞品案例和转化方法 |
| 内容 / 账号运营 | 找热点、看竞品、复盘内容 | 信息源多、重复搜集、难判断业务匹配 | 提供筛选后的情报机会、竞品洞察和历史效果依据 |
| 主编 / 内容负责人 | 审稿、把控质量、沉淀方法 | 标准隐性、判断不一致、复盘难复用 | 将标准显性化、版本化，保留人工判断和升级依据 |
| 知识运营 / 研究人员 | 导入、拆解、审核、整理知识 | 拆解质量不稳、重复过期、缺少溯源 | 管理知识全生命周期、来源、关系、版本和质量 |
| 产品经理 / AI产品经理 | 设计调用逻辑与生产流程 | 不知道用了什么知识，难比较检索与Prompt效果 | 配置任务组包策略、知识模板、评价标准，追踪调用与结果 |
| 决策者 / 业务负责人 | 判断方向、投入和组织能力 | 知识、生产与投放数据分散 | 查看知识使用、生产关联效果及已验证方法；注明证据限制 |
| 合作伙伴 | 项目协作、共享资料 | 文件反复传，边界不清，核心知识易外泄 | 按项目和用途共享，控制查看、调用、下载与授权期限 |
| 商业化客户 | 建立自己的内容知识体系 | 缺方法、积累及历史学习能力 | 建设私有知识空间并接入自有生产流程；商业化能力分期提供 |

### 2、System User：系统用户（后续接入对象）

以下保留长期系统使用场景。首期不以任何生产器接入为验收前提；外部API／爬取工具是信息采集连接器，不等同于对外开放生产知识服务。未来服务账号独立授权，不复用个人登录态。

| 典型系统 | 核心任务 | 当前痛点 | 知识服务价值 |
| --- | --- | --- | --- |
| 选题系统 / Agent | 获取趋势、案例和历史效果 | 模型缺少实时信息与企业经验 | 返回结构化情报、机会依据、案例及选题标准 |
| 脚本生成系统 | 获取项目背景、方法和案例 | 上下文不完整、风格与质量不稳定 | 返回项目上下文、方法、案例、规则组成的知识包 |
| 图片 / 视频生成系统 | 获取人物、场景、视觉规范及Prompt经验 | 跨环节信息丢失、一致性难保持 | 返回固定版本的项目记忆与参考资产，支持一致性控制 |
| 质检 / 评测 Agent | 检查脚本、图片与成片 | 通用评价主观、标准漂移 | 提供版本化标准、反例和评价接口，保留依据 |
| 数据 / 复盘系统 | 回传播放、完播、点击、转化等结果 | 作品、生产过程与实绩无法关联 | 统一关联作品版本、发布记录、知识调用和效果 |
| 外部业务系统 / API调用方 | 检索知识、读取上下文、写回结果 | 数据孤岛、接口与权限不统一 | 标准服务接口、细粒度授权、审计和失败反馈 |

### 3、五类需求与本期承接

| 一级需求 | 能力分类 | 首期承接 | 后续能力 |
| --- | --- | --- | --- |
| 找东西 | 知识发现 | 情报局浏览选题；藏经阁分类检索和学习 | 按生产任务自动检索 |
| 支撑做东西 | 知识服务 | 选题复制／导出、知识人工查阅与引用 | 项目上下文、动态组包、生产器调用 |
| 判断东西 | 评价能力 | 情报局嵌入式选题评价；研判室独立评价与预测 | 外部系统直接发起评价 |
| 管东西 | 知识管理 | 藏经阁导入审核；控制台来源、模板、标准及权限配置 | 项目协作、生产服务配置 |
| 学东西 | 学习复盘 | 研判室按发布链接采集或手工补录实绩、预测对账、验证与知识更新 | 生产记录自动回传、更多平台持续同步、批量校准 |

### 4、四条完整工作流

| 用户任务 | 完整流程 | 完成条件 |
| --- | --- | --- |
| 公网情报与选题 | 控制台配置监测源 → 按计划采集去重聚类 → AI生成选题卡并评价／用户手工记录灵感 → 用户在情报局编辑、比较、选择 → 进入待生产选题池 → 复制或导出交接 | 来源与评价可追溯，选定版本明确，交接记录可查；不要求生产系统API |
| 知识获取与入库 | 情报转入／上传／链接 → 研判室拆解提炼，或人工新增知识 → AI审核 → 人工修订审核 → 原子知识入库 → 分类浏览检索学习 | AI与人工审核均留档，正式知识有来源、类型、适用范围和版本 |
| 内容评价与修改 | 情报标记待研判／自主上传／粘贴链接 → 研判室解析分析 → AI评价、人工判断 → 提炼候选知识送审；需要修改时外部完成后上传复评 | 无需项目或生产器接口；评价绑定实际提交版本，缺失证据明确可见 |
| 发布与效果学习 | 待发布版本评价与预测留档 → 外部立项／制作／发布，最终版本发生变化时在发布前重评 → 粘贴作品链接并关联版本 → 自动提取实绩／人工补录 → AI辅助对账与人工复盘 → 候选规则 → 验证审核 → 更新知识及判断标准 | 同作品版本、同指标与同窗口才能直接对账；无事前预测仍可复盘，但不进入盲预测校准 |

控制台配置属于运营配置流程，不是用户每天选题、学习或评价的必经步骤。一次原始资料采集可同时用于选题和知识加工，两条加工任务及其产物独立管理并关联同一来源。

## 三、前端入口与功能需求

### 1、统一命名与导航

四个一级入口名称已确认，均为三个汉字。界面可配功能说明，但不得将旧能力分类再次展开为一级导航。

| 一级入口 | 功能说明 | 下级工作区 | 核心动作 |
| --- | --- | --- | --- |
| **情报局** | 情报追踪与选题决策 | 情报流、候选选题／手工灵感、待生产选题池 | 查看原文、人工判断、标记待研判，编辑确认与交接选题 |
| **藏经阁** | 知识维护与检索学习 | 正式知识、案例详情、知识新增／修订、审核、回收站 | 浏览、编辑、人工增加、审核、删除；生命周期待细化 |
| **研判室** | 事前判断、事后验证与标准改进 | 内容研判、发布复盘、规律验证 | 接收待研判／上传／链接，分析预测、提炼知识；采集实绩、对账复盘、验证升级 |
| **控制台** | 来源规则与系统配置 | 监测源、采集计划、拆解模板、评价标准、模型配置、权限、任务状态 | 配置、启停、发布配置、检查失败与重试 |

不设置独立项目工作台、项目空间、知识包工作台或生产接入页面。统一搜索、业务线筛选、环节筛选、通知按场景提供；治理动作按权限显示。单个选题、知识或内容详情集中展示来源、版本、相关评价与反馈，避免用户跨入口拼信息。

研判室共用一个入口，内部组织为“内容研判、发布复盘、规律验证”。评价、预测、实绩和复盘分别保存数据，通过同一内容档案与版本关联。控制台负责评价标准的正式配置与版本管理；研判室负责候选规则研究、验证及升级决策，共用Rubric对象，不复制标准库。选题卡内嵌评价与研判室共用评价能力，同一对象、版本和评价任务复用记录；研判扩展维度或对象改版需形成相应新评价。

### 3、四模块的大交互关系

本节对应的图示与精简流程见[四模块交互架构.md](/Users/nathan/Codex_Projects/VideoKnowledgeBase/doc/四模块交互架构.md)；以下保留交接规则、边界与验收口径。

**控制台提供配置，情报局发现内容与选题，研判室形成并检验判断，藏经阁沉淀经审核的知识。** 四者共用来源、内容、版本和审核记录；页面交接通过关联完成，不复制成无法追溯的独立资料。

| 交接方向 | 用户触发 / 系统行为 | 交接产物与边界 |
| --- | --- | --- |
| 控制台 → 其他三模块 | 配置监测源、采集计划、处理模型、拆解模板、评价标准及权限 | 日常选题、研究、知识学习无需重复配置；配置版本可追溯 |
| 情报局 → 研判室 | 在情报流右侧抽屉查看原内容及互动快照，填写S／A／B／C人工评级、修正业务与题材、记录学习点后提交；主页面留在情报流 | 关联原内容、来源ID及版本；人工初判与后续AI评价分开，任务状态可在研判室查看，失败内容同样可研究 |
| 情报局 → 待生产选题池 | AI生成选题或用户手工记录灵感，经编辑确认后选入 | 同一池管理已确认选题；草稿不自动进入；正式生产在外部完成，系统接入后置 |
| 研判室 → 藏经阁 | 多维分析或发布复盘提炼出知识／规则，用户确认提交审核 | 输出候选条目及证据、适用范围；AI与人工审核后才成为正式知识 |
| 藏经阁 → 用户及研判依据 | 用户浏览、检索学习；分析需要时引用已审核知识作为参考 | 知识版本与出处可追溯；不借此恢复首期动态组包或生产API范围 |
| 研判室 → 标准版本库 → 后续研判 | 复盘提出假设，比较新旧规则，验证并审核通过 | 发布新版Rubric或评价提示词等判断配置；控制台与研判室使用同一版本库，不各自修改一套标准 |

**情报选题路径：** `采集情报 → 查看原链接与来源 → AI选题／人工灵感 → 编辑确认 → 待生产选题池`。用户可另将有研究价值的原始内容送研判，两条路径不互为前提。信息优劣标记是个人初筛，不替代正式评价或知识审核。原链接失效、正文缺失应明确提示；仅有标题时不得生成假装基于全文的完整结论。

**情报历史与建议（F-02）。** 情报流支持按业务空间及业务日期查看历史，指标、榜单、达人更新与洞察报告使用同日数据，洞察同时提供建议选题方向。正式服务保存具有稳定ID与版本的情报快照及对应洞察，包含来源、榜单归属与位置、互动数据和采集时间；日期按Asia/Shanghai划分。无历史快照时明确提示，不回退至最新记录或把未知值记为零。历史内容提交研判时保留原快照引用与人工提交的数据，不与其他日期的同来源任务混并；后续采集不覆盖旧日期。保留期限、每日截点、洞察生成时机及更正版本细则继续讨论。原型中的三日快照仅为浏览器本地虚构演示，正式存储及平台采集未接入。

**内容研究路径：** `情报转入／用户上传／用户粘贴链接 → 获取与解析内容 → 多维分析、质量评价，适用时作表现预测 → 用户复核 → 可选提炼候选知识 → AI与人工审核 → 藏经阁`。研判可独立完成，不强制每次都入库。竞品、历史作品和失败案例均可研究；已看到结果的分析不能算发布前盲预测。重复转入时提示已有内容或任务，来源页可关联研判进度与结果；具体呈现方式后续设计。

**观众反馈（F-02，2026-10-09确认）。** 情报评论用于识别情绪、触发原因、受欢迎点与问题点、观众期待及可验证的创作调整。分析保留原文证据、样本范围、采集时间及快照版本；TOP评论仅作证据，不能代表整体观众。展示随业务和情报日期切换，缺失不回退最新、不伪造比例。送研判时冻结本次反馈与原文证据，后续采集不覆盖；反馈观察不自动成为正式质量评分、事前盲预测或已验证知识。原型用明确标注的虚构评论与固定归纳演示，真实平台采集、分析模型及样本可信门槛继续细化。

**自有内容验证路径：** `待发布内容评价并冻结预测 → 外部立项／制作／发布 → 用户粘贴发布作品链接 → 确认作品版本与原预测关联 → 自动采集或人工录入实绩 → 对账复盘 → AI提出候选假设 → 人工复核及样本验证 → 审核启用新标准／知识 → 下一轮判断`。立项可以先于研判，关键约束是用于校准的预测必须在对应版本发布前冻结；有发布结果但无事前预测仍能复盘。

研判室对已立项并发布的内容记录轻量立项信息、内容ID、版本、平台发布记录及必要外部标识，不新增项目工作台。早期选题／脚本与最终成片建立前后关联；内容有实质变化时重新进行最终版本的发布前判断，不能用脚本评分直接冒充成片预测。

“待生产选题池”是原“待创作选题库”的统一名称。藏经阁负责双审后的知识浏览、编辑、人工新增和维护；实质修改形成待审新版本。删除先进入回收站，30天后自动永久删除；其他生命周期、恢复规则、历史引用处理及具体审核页面继续待讨论，不将过期或低使用率自动视为删除理由。

### 4、研判室发布数据与判断改进闭环

**作品链接与数据。** 用户粘贴发布链接后，系统识别平台与作品，提示关联既有内容版本，再通过已支持的平台连接器提取转发、评论、点赞、收藏等可获得指标。用户可手工录入、导入或更正。同时保存发布与采集时间、平台、账号、指标口径和数据来源；能获取时记录播放量、投放及分发条件，供复盘解释。不能保证任意链接都有完整指标，平台与页面支持范围后续逐项确认。

**快照与缺失。** 每次采集或手工输入形成带时间的数据快照；更正保留原值、修改人和原因，自动更新不得静默覆盖人工修订。无法获取显示未获取，不显示为零；链接识别／采集失败可人工补录。关注观察窗口对应的快照，不把多次累计点赞数相加，也不拿较晚累计值伪装成较早窗口实绩。刷新频率与更正冲突的操作细节留待模块设计。

**预测与对账。** 预测在发布前锁定内容版本、目标指标、观察窗口、区间或等级、理由、标准／模型或提示词版本和服务端冻结时间。仅在版本、指标、窗口及关键发布条件可比时直接对账；差异需标识并分析。质量评分、表现预测、实际表现分别保存，不能用总评分替代市场预测，也不能将账号、流量与投放影响全部解释为内容因素。

**判断模型如何完善。** 本期“完善判断模型”优先指迭代Rubric、规则适用条件、参考案例与评价提示词，不默认需要模型训练。采用已讨论的Cheat on Content闭环思想：`留档判断 → 核对结果 → 提出偏差假设 → 候选版本 → 新旧版本回测与独立样本验证 → 人工审核 → 生效／回退`。单条爆款只提供假设，不能自动改写正式标准；样本不足继续保留候选。对未发布、放弃、低表现内容保留相应状态和原因，避免只挑成功样本学习。

规则验证通过后，知识候选进入藏经阁审核发布，判断标准进入控制台共用的版本库；新判断使用生效版本，历史报告和预测继续绑定原版本。具体评分维度、验证指标与门槛在模块细化时确定。

### 1、后端模块分工

| 评价与预测 | Rubric版本、评价任务、证据、复核、版本对比、预测冻结 | 情报局内嵌评价、研判室；控制台配置 |

### 2、首期核心数据对象

| 对象 | 内容与关键关联 |
| --- | --- |
| Source / CollectionJob / RawAsset | 监测源、频率与用途、采集任务及原始资料；证据可定位段落、页码或视频时间段 |
| IntelligenceSnapshot | 快照ID／版本、业务日期、来源与榜单／达人归属、原始内容及互动指标、采集时间；关联同日洞察与选题建议，供历史浏览及研判引用 |
| TopicCard | 选题内容、来源、业务、人群、时效、版本、AI与人工编辑、评价引用、选用及交接状态 |
| KnowledgeItem / Relation | 原子知识、类型标签、证据、双重审核、状态版本；关联来源、案例及其他知识 |
| ArtifactRef（轻量内容档案） | 内容ID、版本、业务、类型、正文／文件与参考、立项／采用状态及可选外部标识；关联选题、前序内容及评价，不承载项目排期 |
| Rubric / Evaluation | 标准版本、维度、权重、硬规则；对象版本、AI结果、证据及人工复核 |
| Prediction / Publication | 服务端冻结预测、目标条件；内容版本、发布标识、平台账号及真实发布时间 |
| Performance | 发布ID、转评赞藏等指标、定义／分母、数值、观察窗口、采集时间、自动或手工来源及修订；保留快照，不覆盖历史 |
| Review / ValidationRun | 预测实绩关联、偏差及条件差异、候选知识／判断配置、训练或调参样本与验证样本区分、原新结果、审核及回退决定 |
| Member / Grant / AuditLog | 成员、组织与对象授权、操作范围、到期撤销、关键行为审计 |

情报链：`Source → RawAsset → TopicCard版本 → Evaluation → 人工编辑／选择 → 待生产选题池`。

知识链：`RawAsset → KnowledgeItem草稿 → AI审核 → 人工审核 → 已发布知识 → 人工检索学习`。

评测闭环：`ArtifactRef版本 → Evaluation／Prediction → Publication → Performance → Review → ValidationRun → KnowledgeItem／Rubric新版本`。预测可缺省，但不完整链条不能进入盲预测校准统计。

TopicCard与内容档案通过ID／版本关联，选题阶段评价不复制为成片评价。同一作品可多次发布、同一发布可有多个指标窗口；不用文件名或标题代替关联键。ProjectContext、TaskServiceConfig、KnowledgePack、ServiceCall、GenerationRun及生产ServiceAccount均后置。

### 3、状态、版本与异常

- 选题：候选、已选／待生产、已交接、已采用、已放弃等状态记录用户操作；首期采用结果由人工维护，不把导出自动判成生产完成。具体状态名和撤回操作在情报局细化。
- 知识：已确认草稿经AI与人工审核后发布；修改需保留版本，删除进入回收站并在30天后自动永久删除。待复核、停用、归档等生命周期状态仍是建议，详见藏经阁待讨论项。
- 处理任务：`排队 → 处理中 → 成功／失败`；失败保留原因、输入版本及重试记录，重复提交不重复发布业务对象。
- 评价：`待处理 → 执行中 → 已完成／证据不足／失败`；新内容版本与重跑产生新记录，人工复核追加留档。
- 预测：`草稿 → 已冻结`；撤销追加记录、不改原值；更换内容版本需重新判断，不能把事后录入伪装成事前预测。
- 学习候选：`待验证 → 验证中 → 待审核 → 已生效／已否决`；样本不足继续待验证，回退产生审计记录。

来源过期／撤回时标识受影响选题与知识并提示用户；未授权历史正文不可因旧记录存在而继续读取。实绩迟到或更正保留事件时间、导入时间与修订，提示相关复盘需更新，不静默改写已确认结论。缺失数据与零值分开展示。

### 4、接口边界与技术约束

本期需要两类接口：一是外部情报及发布效果采集适配接口，二是支撑本系统页面的内部应用接口。对生产系统开放的检索、项目上下文、组包、评价调用及生成记录回传接口后置，具体契约未定。

内部能力包含原始资料提交与处理状态、选题卡编辑选择与导出、知识审核检索、内容版本提交与评价查询、预测冻结、发布链接关联、实绩自动采集与手工录入／导入、复盘与验证决策。写入需防重复提交、版本冲突可识别，长任务可查询状态；导入缺关联键或口径不兼容时明确提示。

沿用[业务架构图.md](/Users/nathan/Codex_Projects/VideoKnowledgeBase/doc/业务架构图.md)的技术建议：结构化对象与关系可用PostgreSQL及JSONB，语义与全文检索组合召回，对象存储管理素材。组件选型不作为产品界面概念；本版不绑定具体模型或生产器。

所有入口执行服务端授权，日志不暴露密钥；任务失败可见、重试可查。删除正文需处理关联影响并保留允许保留的审计标识。性能、并发、成本阈值在数据规模和模型方案明确后确定；首期验收不要求未经确认的外部连接器或生产系统在线。

## 五、首期范围与验收

### 1、阶段范围

四入口和“项目／生产集成后置”为已确认决策。各平台连接器、格式支持深度、评价细则及阈值将在模块讨论中确定；不得因此把已确认的定时采集、AI选题与评价、AI加人工入库审核、约定平台发布链接的实绩提取整体降级为未来功能。发布效果采集不依赖生产器API，与后置的生产系统集成分别验收。

### 3、首期效果验证口径

先积累基线再设目标，避免将平台波动归因于知识库。首期指标不依赖生产系统自动回传。

| 指标 | 口径 | 注意事项 |
| --- | --- | --- |
| 选题选择率 | 同一批已展示候选中，进入待生产选题池的唯一选题数／已展示唯一选题数 | 明确观察窗口，区分未看、未选、放弃；不等于实际生产或发布率 |
| 知识审核通过情况 | 对同批拆解条目统计通过、修订后通过、驳回与待审核 | 防止用堆积条目或减少审核提高表面入库量 |
| 来源版本可追溯率 | 正式知识及评价所用证据中，可解析到对应资料和版本的引用项数／同批引用项总数 | 撤权不可读与引用丢失分别统计 |
| 评价人工采纳情况 | 已完成复核的同批评价中，认可、部分认可、否决及证据不足的分布 | 认可不等于预测准确，必须保留覆核理由 |
| 发布复盘覆盖率 | 同批已达到观察窗口且纳入跟踪的发布中，已有实绩并完成复盘的记录数／该批发布总数 | 无预测也可计入复盘覆盖；缺预测不能计入盲预测样本 |

盲预测校准另设合格样本集，要求发布前冻结、对应版本一致、指标窗口匹配；报告样本量、预测误差或区间覆盖，不能将无预测或事后判断混入。评价一致性、人工检索效率可在试点后补充测量。知识包采用率与生产效率增益后续接入生产系统再验证。

### 4、下一轮模块细化议题

按四个已确认入口继续讨论，以下细节尚未拍板，不影响本版整体边界。

1. **情报局**：监测源与原链接浏览、卡片字段、人工初筛、待研判交接、AI／手动选题编辑确认与待生产池状态。
2. **藏经阁**：候选知识双审、正式知识结构、分类检索、新增编辑、生命周期、回收站恢复及30天永久删除的关联影响。

4. **控制台**：角色权限、来源与模型配置、模板及标准发布、失败重试、运行用量与成本呈现。

模块细化后再确定数据规模、性能成本目标和交付计划；项目工作台与生产接口不作为本轮细化的前置条件。
