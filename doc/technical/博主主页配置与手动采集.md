# 博主主页配置与手动采集

版本：v1.1｜日期：2026-10-22。用户确认：情报流选择“博主”后，在筛选区下方增加“配置博主”，批量填写主页；同步单文件Demo。首批支持抖音，保存不采集，沿用“重新采集”手动获取更新，暂不启用定时任务。

## 一、配置与存储

2026-10-22最新界面：情报流“博主 → 配置博主”和控制台“采集配置 → 监测博主 → 管理监测博主”共用`frontend/src/components/CreatorConfigDialog.tsx`及同一组主页接口／缓存，单HTML Demo两处共用creatorDialog。桌面弹窗左侧批量填写、右侧已配置清单及逐项“删除”，保留业务线选择；≤640px上下排列。原控制台单UID表单不再作为主页监测入口，既有UID来源及历史数据保留，不自动补造主页或迁移成主页订阅。删除只移除当前监测配置，不删除历史作品。

`GET /api/v1/intelligence/creators?business_code=…`读取本业务配置；`POST`同地址接收business_code及links（每行一个）；`POST /api/v1/intelligence/creators/remove`接收business_code及creator_id。三个接口均检查当前source.configure，写操作沿用Origin、CSRF和UUID幂等回执，先授权再重放；组织来自会话。每次请求最多100行／16000字符，每业务最多50位，空行忽略；逐行返回added／duplicate／invalid／limit，合法行可独立保存。

只接受HTTPS、精确douyin.com或www.douyin.com、`/user/<标识>`路径；拒绝账号密码、非443端口、视频地址、短链及其他平台。统一www域名，去查询、锚点和末尾斜线后去重。主页中的sec_uid不冒充UID。

配置保存为既有raw_assets中的manual不可变版本（business、items[id/url]、提交人、SHA）；audit_events以creator.config.saved＋业务范围指向最新版本，按原包captured_at排序，避免事务内CURRENT_TIMESTAMP相同造成乱序。写操作在组织事务锁下合并当前名单；移除追加版本，保留旧证据，不删除作品。无新增表、迁移、调度或授权。Demo仅localStorage交互演示，与正式数据库分开。

## 二、显式取数与证据

[手动刷新](情报流手动刷新.md)冻结当前业务的主页名单与配置原包。仅有名单时增加“博主”渠道；未配置时原四渠道保持。执行前检查唯一启用的红狐连接和已有密钥，否则不请求主页或作品。

先查既有可访问、未撤回的sec_uid别名证据，且须唯一指向数字UID；找不到才创建creator.resolve独立任务（一次预算、一次尝试）。请求前提交creator.profile.requested审计，普通HTTPS GET仅访问已规范化的抖音主页：不带Cookie、不跟随跳转、不执行脚本、无签名绕过、20秒超时及2MiB上限。读取内联RENDER_DATA／__NEXT_DATA__ JSON中明确user／userInfo节点，要求sec_uid与目标主页相同、UID为有效数字且无冲突；推荐视频author不作为身份依据。原响应保存为processing证据并绑定任务输入，完成状态记录HTTP及固定错误码。task_outputs与真实账号别名只在当前权限／租约下发布。

解析外调通过专用审计计入external_calls／unresolved_calls；崩溃后的请求不自动重发，通用队列不接管creator.resolve或refresh子任务。身份无法核验、跳转、受限或网络结果不明均保留证据并失败，不继续付费作品请求。

UID确认后复用红狐[douyin.creator.works文档](https://redfox.hk/apis/douyin/QSL2ZSXM)对应`POST /story/api/dy/data/listWorkByAccount`，固定userId=已验证UID、pageNum=1、pageSize=3，每位最多3部；返回作者UID继续严格匹配，不翻页、不重试、不调用评论或模型。作品子任务绑定确切身份原包，建立独立暂停的“监测博主”来源，临时启用后finally暂停；不复用或关闭控制台其他既有计划。

博主之间串行至少10秒；作品通过collection_calls的10秒持久门禁、主页通过数据库级事务锁及已提交请求审计的10秒门禁覆盖跨批次与进程重启，冷却中不追加请求；同批UID去重，不因多个主页重复请求。每次都检查当前名单和权限，移除后不再发起该博主后续请求；在途外部事实仍保留。成功形成creator_works不可变当天快照；失败来源保留旧数据，成功成员可按渠道部分发布，历史日期不改写。点击重新采集仍会刷新其他现用渠道，TikHub及红狐均可能产生费用。

## 三、验收边界

使用隔离PostgreSQL与模拟HTTP验证保存零调用、业务隔离、逐行校验去重、移除、UID解析、一次作品请求、身份证据复用、来源暂停、主页受限不触发付费请求及旧刷新回归。正式页面只读检查入口、弹窗、空名单、关闭后焦点归还和双主题；未向真实工作区插入测试博主，未调用真实平台／付费API／模型。

目前没有用户提供的真实博主主页，真实网站可能返回风控页或不包含支持的内联数据；工程测试通过不等于实际账号取数成功。后续用1～2个实际主页人工验收，必要时在同一证据／预算边界内扩展解析格式；不自动切换供应商或增加付费身份接口。证据与结果见[本轮记录](../plans/2026-10-22-博主批量主页配置.md)。
