## 一、当前工程与边界

前端采用React 19、TypeScript、Vite 8、React Router 7和TanStack Query 5，具体版本以[前端配置](../../frontend/package.json)及[pnpm锁文件](../../pnpm-lock.yaml)为准。React负责侧栏、顶栏、面包屑、业务切换、主题入口、Tab及闪念入口；模块工作区登记在 `frontend/src/modules`。当前6个真实页面由React组件渲染，其余9个工作区的列表、详情、表单仍由 `frontend/src/demo/runtime.js` 这个受限DOM区域渲染，**尚未全部组件化或接真实接口**，不应在此层新增正式业务逻辑。

过渡层存在的目的是保留Demo基准，后续按“情报流 → 研判 → 候选知识与双审”逐页迁成带类型的React组件，再接OpenAPI契约。每迁移一页须对照原Demo验证后移除相应旧渲染，不保留两套并行业务状态。不得直接把Demo localStorage当数据库、将模拟审核或任务作为正式能力。

后端为FastAPI，依赖锁在 `backend/uv.lock`。当前有 `/api/health`（API进程状态、服务名和版本）及 `/api/v1/session` 的登录／读取／退出接口；`/openapi.json` 是已实现接口的唯一机器契约，后续业务接口须据此生成前端类型。S05.5的 `frontend/src/api/client.ts` 与Provider已接会话／文件及统一错误分支，控制台采集与运行页、情报流已消费真实请求，其他业务页尚未迁移；不会静默回退Demo。PostgreSQL／pgvector与Redis环境已在S02独立验收，S04已建立70表、4次迁移、数据库事务及受限应用登录，见[迁移与恢复](数据库迁移与恢复.md)；S05.2已落实会话／公共权限／审计及增量3表，S05.4已接Celery／Redis／Beat，S06.1已接红狐采集处理器，S06.2已接来源计划，模型任务仍待后续；供应商验证见[采集清单](采集能力与样本清单.md)。

## 四、本地基础设施与后续顺序

`infra/compose.yaml`提供PostgreSQL 17＋pgvector、Redis 7.4，项目名固定cip-local。为保留本机原有5432上的PostgreSQL18，项目只绑定127.0.0.1:15432和16379。本轮使用独立Colima profile `cip-local`（2核／2GiB／20GiB，不挂载主机目录）；全局Docker context仍为default，通过根目录.env的CIP_DOCKER_CONTEXT显式选择colima-cip-local。实际配置文件权限0600，不提交Git、不输出密钥。

```bash
# 首次安装后或重启本机后，启动本项目Docker engine
colima start cip-local --runtime docker --vm-type vz --cpu 2 --memory 2 --disk 20 --activate=false --ssh-config=false --mount none
# 原子创建本地随机口令配置；已有.env一律保留
pnpm infra init
pnpm infra up
pnpm infra status
pnpm infra check
```

依赖安装方式为 `brew install colima docker docker-compose` 和 `cd backend && uv sync --frozen`；脚本支持独立docker-compose或Docker Compose插件，不修改用户全局Docker CLI配置。Docker Desktop用户可在自己的.env中将CIP_DOCKER_CONTEXT改为default。POSTGRES_PORT、REDIS_PORT及两个连接URL必须对应；改口令须同时更新DATABASE_URL，已有卷的数据库口令不能仅靠修改.env自动轮换。

`pnpm infra up`运行Compose并从宿主机连接数据库／Redis，在专用项目空库启用vector扩展；`check`验证实际连接、vector计算、Redis PING及AOF，不写业务表。API `/api/health`只说明API存活，不能替代 `infra check`。S02使用psycopg／redis执行验证；S04已接入SQLAlchemy／Alembic及业务迁移，S05.4已接Celery调度，业务服务按S06以后逐步接入。

明确执行隔离数据与重启验收时使用下列命令；restart-proof仅重启cip-local的两个容器，会造成短暂本地依赖中断，不用于日常在线检查：

```bash
pnpm infra probe
pnpm infra restart-proof
# 仅停止项目容器，保留全部卷；之后infra up恢复
pnpm infra stop
# 可选：停止整个项目虚拟机，数据磁盘保留
colima stop cip-local
```

probe使用随机schema和Redis键，验证提交、回滚及AOF落盘；restart-proof验证重启后同一标记仍在，再只清理本轮专用表、schema、键。不执行卷删除或任意库表清理，已有未完成探测不被覆盖；结果在忽略Git的data/s02-proof.json。本次已验证PG17.11、pgvector0.8.7和Redis7.4.11，见[连接](verification/2026-10-16/infra-connections.json)、[重启持久化](verification/2026-10-16/infra-persistence.json)、[清理与空库](verification/2026-10-16/infra-cleanup.json)。

本机网络的镜像下载、VM解析及daemon代理处理见[本轮执行记录](../plans/2026-10-16-S01-S02执行记录.md)；所有修复限定项目VM，未改主机DNS或TLS校验。用户现有本地代理关闭时，新的镜像拉取可能失败；现有已下载镜像和本地服务不以外部API成功为前提。`data`不提交运行资料，服务器接入与正式部署仍后置。

S01已由用户指定AI漫剧／抖音／红狐，真实响应、素材与费用见[采集清单](采集能力与样本清单.md)。后续首次真实填充先移除对应演示数据，小量接入，空数据和错误不得回退Demo。继续按[研发实施计划](../plans/研发实施计划.md)完成来源样本、数据设计、业务迁移与公共服务；S02通过不等同技术方案工程基础阶段整体完成。
