# 文件存储与访问

版本：v0.1｜日期：2026-10-16｜状态：S05.3已完成。依据：[接口契约](接口契约.md)、[权限状态](数据字典-权限与状态.md)及[执行记录](../plans/2026-10-16-S05.3文件存储与安全访问.md)。Demo不变。

服务契约：POST /api/v1/files使用application/octet-stream原始流，query含work_id、expected_work_lock_version（十进制字符串）、original_name、media_type，须cookie／CSRF／UUID Idempotency-Key。POST /api/v1/files/from-url接受上述元数据＋url的JSON，直接HTTPS素材主机须配置允许；GET /api/v1/files/{file_id}/content返回attachment二进制，可选parent_kind（works／artifact_versions／raw_assets）、parent_id必须同时出现。直接文件ID仅org／file范围file.read；父对象先读取并核验实际关联，上传接收关联也是明确Work→File关系。创建回应仅安全File元数据，不泄露storage_key或外链查询串。

增量字典：0006_storage新增file_intakes，复合主键(org_id,file_id)，同租户FK file_objects、works、members；work_id、created_by非空UUID，created_at非空timestamptz默认clock_timestamp，origin_kind为upload／external，source_url仅external非空。记录不可更新／删除；文件属于唯一作品，ArtifactVersion引用该file_id时work_id必须一致，旧文件未有intake不受此新增来源约束。正文版本依然不可变，当前指针变更继续走S04 CAS／封存约束；上传不替代正式材料创建。

存储位置为STORAGE_ROOT下files专用私有目录；相对STORAGE_ROOT按backend目录解释，默认项目data。对象key由服务端组织UUID／文件UUID生成，文件名仅展示，不参与路径。临时、journal及对象目录拒绝符号链接，写入不覆盖，限大小并校验摘要。仅管理命令恢复本服务创建且格式合法的journal，锁组织后查询真实File记录及intake；未知提交结果留存待恢复，不能直接清空目录。

安全依据：[OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)、[Python HTTPSConnection](https://docs.python.org/3/library/http.client.html)。文件格式校验与网络安全分别验收，不把模拟远端响应计作真实供应商实测。运行细节与证据完成后回填。

## 一、启动与使用

`pnpm db:upgrade`新增0006_storage（74表），自动刷新受限应用角色；STORAGE_ROOT默认为项目data，既有示例`../data`按backend解释。files、objects、staging、journals目录要求当前用户所有且权限700；对象文件600。路径的任一符号链接均拒绝，macOS临时目录请用真实/private/tmp，不把/var或/tmp的系统符号链接当受控目录。目录权限不合格时修正运维配置后重试，不自动放宽校验。

MAX_FILE_BYTES默认52428800，配置硬上限268435456；真实写入分块累计计算，不信Content-Length。EXTERNAL_MEDIA_HOSTS为精确小写主机JSON数组，默认[]；只允许HTTPS/443，无userinfo、fragment、IP字面量、控制字符或Unicode域名，所有DNS回答须为有效公网地址。连接使用已校验数字IP，TLS仍校验证书及原始主机名；不读取环境代理、cookie或Authorization。逐跳重定向最多3次，每次重新走主机／DNS／IP校验；DNS并发最多2，每次等待最多5秒，连接读取超时5秒、外链总截止20秒并以关闭socket中止，单次read1避免慢速填满read(n)。未取得成功素材不落库、不调用AI或自动重试。

例：已有有权成员session后，`POST /api/v1/files?work_id=<UUID>&expected_work_lock_version=1&original_name=script.txt&media_type=text/plain`，Content-Type为application/octet-stream，body为真实文件字节；带当前cookie、精确Origin、X-CSRF-Token及UUID Idempotency-Key。上传前后均验证当前content.write及目标可见性；expected_work_lock_version只在首次生效检查，成功回执重放不因后续作品变更而失败，但仍须当前授权。外链JSON与文件upload query字段相同，另加url；相同输入的外链重放先查回执，不再次联网；新的key代表新请求，可能产生新文件。

文件响应包含id、created_at、original_name、media_type、byte_size十进制字符串、sha256及accepted，不含storage_key／source_url。文件来源与最终重定向URL保存在受控file_intakes；原URL在回执中只参与摘要，不写审计详情。metadata JSON限定16KiB（传输保护早于业务鉴权）；文件字节流最多MAX_FILE_BYTES。错误码：INVALID_FILE／UNSAFE_URL为422，FILE_TOO_LARGE为413，FETCH_FAILED为502，磁盘／数据库未就绪为503；均使用脱敏信封，不回显路径或URL。

## 二、格式与权限边界

允许txt／md／srt（UTF-8，非空、无非法控制字符，拒绝HTML／脚本／SVG标记）、PDF（头与尾部结构）、MP4（完整顶层box及ftyp／moov／mdat）、PNG（签名／长度／CRC／尺寸／关键chunk）、JPEG（签名／结束及图像、扫描标志）。扩展名、声明MIME和实际内容必须匹配；ZIP／DOCX／可执行文件及其他格式明确INVALID_FILE。基础结构校验不是完整解码或病毒扫描；PDF脚本、压缩图像及容器内容仍是不可信输入，后续解析器必须隔离运行并限资源，不自动打开或执行。

GET content只返回application/octet-stream、attachment、nosniff、no-store及长度。直接访问仅org／file Grant；指定works父路径时，接受真实cover_file_id或file_intakes接收关联，其他版本／原始资料父路径只接受其实际file_id。不同父对象、不同版本、不同组织均不能替代正确关联；每次下载先验完整父依赖，核对磁盘字节数和SHA256，发送前再验权限，后续每个64KiB分块也重新鉴权。撤权后终止后续分块，已发送字节无法追回；流开始后无法把HTTP200改成401，应视为下载中断。无长期公开URL、静态目录映射、Range或内嵌预览。

## 三、提交、恢复与审计

临时流按随机名写入并持有flock，sha与大小增量计算；最终事务先取组织锁并重新鉴权，journal fsync→不可覆盖hardlink对象并fsync目录→File／Intake／稳定ID回执／上传审计提交→确认journal。若失败且已发布，另事务以组织锁查询真实File记录；未提交则移除本次对象，已提交则保留，数据库不可达时保留journal和对象。不能因Python收到提交异常就删除字节，也不能用单一finally假装跨系统原子提交。

`pnpm files recover`由持有专用本地私密配置的维护者执行，使用受限应用角色；不使用通用超级用户或系统成员。恢复只遍历合法UUID journal，对其组织锁等待最多2秒、查询最多5秒，核对已提交对象hash／大小，清理未提交对象并记录脱敏审计；无法确认则计入unresolved、保留journal，命令非零退出。正在使用的stage由flock保护；无journal且超过1小时的合法.part文件才可清理；仍被未解决journal引用的stage不删。无全盘删除、无业务文件“过期自动清空”。

file_intakes不可变；任何ArtifactVersion使用已登记file_id时work_id必须与Intake相同，两个方向都在提交前验证，避免先写版本后登记绕过。材料version及指针仍沿S04封存／CAS；上传仅接收文件，不宣称已解析或完成研判。文件缺失／篡改会拒绝下载，不能回退同名文件或其他版本。0006 downgrade删除Intake来源与范围记录，只适用于隔离验收；已上传运行库应备份并采用前向修复，不能把降级当清理命令。

## 四、验证入口

`pnpm api:generate`／`api:check`维护40项设计目录（6项业务已实现：3会话＋3文件），运行OpenAPI另含health。`bash scripts/check.sh`包含类型与契约漂移；`pnpm db:test`使用随机隔离库及临时私有目录，验证真实字节、回执、撤权、版本、受限角色和恢复，证据使用s053前缀，不覆盖S04／S05.2。前端真实请求和交互接入留S05.5，Demo及原型保持不变。

最终验收：78项普通后端、95项真实PostgreSQL／私有文件系统、7项前端及16条类型断言通过；合法PDF／MP4／PNG／JPEG小样本由本地生成，测试无需依赖ffmpeg。一次独立审阅的总截止问题已补真实socket生命周期回归；公开HTTPS文本8008字节实测通过，项目库0006_storage共74表仍仅4条全局配置。证据及限制见[执行记录](../plans/2026-10-16-S05.3文件存储与安全访问.md)。
