# 四模块交互架构

版本：v2.2｜日期：2026-10-15。对应[可编辑draw.io图](四模块交互架构.drawio)与[静态预览](previews/四模块交互架构.png)，用于快速理解模块交接；需求范围和整体验收见[主PRD](AI知识库产品需求文档_PRD.md)，最新局部交互见模块文档。

**控制台提供配置，情报局完成情报初筛与选题，研判室按业务和作品组织分析、质量评级与市场预测，藏经阁承接双审后的知识。** 内容研究可直接沉淀知识，发布后验证是另一条分支，不作为研判或知识入库的前提。

**前端基准（2026-10-15确认）：必须严格按[当前Demo](prototypes/index.html)开发，用户指定的[研判室入口](prototypes/index.html#2/0)已核对。** 本文及架构图说明业务边界和模块关系，不替代Demo的页面与操作；若旧页面描述与Demo不同，以经用户确认的Demo为准。真实数据、权限和审核规则仍按PRD实现，未展示交互另行确认。本次仅同步开发基准说明，业务连线未改变。

## 一、四模块职责与交接

| 模块与依据 | 本模块职责 | 交接对象与规则 |
| --- | --- | --- |
| [控制台](modules/控制台.md) | 按业务管理榜单类型、监测达人、采集计划；配置按业务／材料适配的拆解模板、模型、评价标准、权限和任务运行 | 向三个模块提供带版本的配置；接收研判室经独立验证、人工批准的标准版本，共用同一正式标准库 |
| [情报局](modules/情报局.md) | 情报流、选题卡、待生产；浏览榜单／达人原链接，抽屉内填写人工初评；AI选题和手工灵感统一编辑确认 | 来源ID、内容与互动快照、SABC、学习点／评价、修正标签 → 研判室待分析记录；确认选题 → 待生产选题池 |
| [研判室](modules/研判室.md) | 内容研判、发布复盘、规律验证；汇集资料，按作品／单集及材料版本分析，输出质量与市场判断，复核并提炼候选 | 用户选中的候选知识及证据、版本、审核记录 → 藏经阁；验证批准的评价标准 → 控制台；报告可独立留存 |
| [藏经阁](modules/藏经阁.md) | 候选接收、人工新增、AI与人工审核、正式知识浏览检索、修订及回收站 | 正式知识与案例带来源和版本供用户学习及研判参考；共用审核对象，同版本同类审核复用，实质修改须复核 |

情报局只提供榜单／达人筛选，其名单和榜单类型的新增移除在控制台。顶部公共栏提供“业务空间”`AI漫剧｜故事短片｜电商短视频`，默认故事短片、单选且跨一级模块与二级工作区保留；情报局、研判室、藏经阁的列表、指标及报告均限于所选业务，页面不重复选择。共享知识按适用标签显示；业务空间仅表示数据范围，不引入项目管理。每条原始情报标一条业务线，当前不设生产环节筛选。卡片布局、分页等局部细节留在情报局文档，不展开为架构节点。

## 二、选题与研判输入两条路径

**选题交接：** `采集情报 → AI选题及评价／手工灵感（含闪念胶囊）→ 编辑确认主业务线 → 待生产选题池 → 复制或导出交接`。选题确认无须先研判，草稿不自动入池；导出不代表已生产。

**情报送研判：** `榜单／达人条目点击“研判” → 右侧抽屉人工初评 → 提交待分析记录`。用户仍停留情报流；SABC、修正业务／题材、学习点或文字、来源ID及互动快照交给研判室。修正标签仅写研判记录，不覆盖原始采集标签。同来源已有待分析任务则更新并留档，已有完成报告则新建任务，不覆盖历史；结果如何回显情报流仍待细化。

**直接输入研判：** `链接／文件／手工文本 → 解析预览 → 确认业务、作品归属和材料类型 → 人工初评 → 待分析`。情报局已填初评直接带入，资料不足先补充。三类业务共用处理流程，但分别使用匹配的知识结构、拆解模板与评价标准，不拿成片标准评仅有文本的资料。

## 三、作品组织、分析与知识入库

组织关系为 `作品 → 单集／片段 → 材料及版本`，整部作品级资料可直接关联作品。漫剧支持多集、批量上传、排序与补集，显示已收集／已分析范围并切换全剧／单集结论；短片以单部作品组织，无需强制显示“第1集”；电商作品关联商品及创意版本。作品容器仅服务研究，不引入生产项目管理。

| 报告部分 | 内容及后续动作 |
| --- | --- |
| 内容拆解 | 按业务与材料类型呈现结构，并关联视频时间点或文本证据；部分集数不能冒充全剧 |
| 综合判断 | AI质量等级、分项判断与市场指标预测并列；显示条件、区间、依据、不确定性及所用标准版本 |
| 人机分歧 | AI首次质量评级不读取人工等级和倾向性评价，独立判断后与人工初评对照，AI审核与人工复核留档 |
| 候选知识 | 用户编辑、拆分、合并和勾选送审，保留来源、版本、适用条件、限制及可得反例 |

**直接研究入库：** `分析报告 → 选取候选知识 → AI审核＋人工审核 → 藏经阁正式知识`，无需先发布或复盘。候选也可来自发布复盘或用户手工新增；案例观察与有效性假设分开标注，声称改善效果的方法须验证。

报告可留在研判室，完整报告有保存价值时可作为案例型知识送审。报告复核不自动批准全部候选条目；研判室与藏经阁共享审核记录，避免同版本同类审核重复执行。已审知识回流供研判参考，不绕过权限和来源版本校验。

## 四、市场预测、发布复盘与标准回流

**发布验证：** `AI市场预测与发布前冻结 → 外部发布并关联链接／内容版本 → 自动采集实绩或人工补录 → 预测值—实际值—偏差 → 人工复盘 → 候选规律／标准 → 独立样本验证 → 人工批准`。

- 市场预测不能以SABC或“有爆款潜力”替代：条件具备时提供播放、点赞、评论、转发、收藏等具体指标区间；电商可在数据充分时补充点击与转化。绑定平台、账号、投放条件、指标定义、观察窗口、作品／单集版本及服务端冻结时间。
- 条件不足显示“暂不可可靠预测”，质量证据不足显示“暂不可评”，均不以零值或C级替代。漫剧单集与整部作品预测分开，不简单相加；全剧汇总口径仍待细化。脚本等早期判断不冒充最终成片版本预测。
- 同版本、同指标、同窗口且发布条件可比才直接对账；累计快照不相加，较晚数据不替代目标窗口。已看到表现的外部案例属事后分析；无事前预测仍可复盘，但不能计入盲预测校准。
- 第一版标准来自专家经验和人工标注案例；人工意见、内容分析及复盘提供修订线索，不把人工高分或高播放当作标准答案。新旧标准使用独立样本验证，样本不足保留候选。
- 知识候选经双审进入藏经阁；标准候选经验证及人工批准进入控制台共用版本库。报告展示当前使用标准，规律验证展示修订与验证依据；新标准不改写历史评价和预测，可停用或回退。

## 五、共同边界与读图说明

跨模块引用同一来源ID、作品／单集ID、材料版本、发布记录及数据快照。情报、选题卡、报告、知识条目保持各自语义，不因共享原始资料而合并为一个对象；判断、审核和市场数据分别留档。

正式剧本、资产、成片制作及平台发布发生在外部；项目工作台、动态知识包和生产器接口后置。外部采集按平台实际支持能力接入，不默认任意链接均可解析；原型演示不代表真实连接器或AI已接通。主动删除知识进入回收站，30天后自动永久删除；其他生命周期与恢复细则另议，过期不自动删除。

图中实线表示配置、处理或业务交接，不意味着所有用户都必须依次完成全部节点；绿色虚线表示已审知识供研判参考，橙色虚线表示经验证批准的标准回到控制台。模块交接图保持原有处理与回流关系；顶部业务空间是展示范围调整，不新增交接节点。本文按情报局v0.12、研判室v0.4及控制台v0.2同步，详细评分阈值、预测门槛与页面控件仍以模块后续讨论为准。
